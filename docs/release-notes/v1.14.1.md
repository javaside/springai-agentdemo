# springai-agentdemo v1.14.1

在 [v1.14.0](v1.14.0.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版修复两处**界面可见性缺陷**：模型输出期间**输入框上下闪出第二条边框**（反复出现又消失），以及**大量次要文字在深色终端下几乎看不见**（状态行后缀、面板说明、引用块等）。两处都只有在真实终端里才看得见，本版为它们各补了实机回归验证。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.14.1-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.14.1-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.14.1`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.14.0 的变化。

## 修复：模型输出期间输入框不再闪出第二条边框

模型流式输出时，输入框上下会反复闪出多余的边框线，输出结束后消失——用户实报「反复这样」。

根因在行内渲染的**高度变化方向**。本 TUI 的 live 区贴着屏幕底部，输入框与状态行永远是最后几行；而流式预览行长在输入框**上方**，随 token 不停出现又消失，live 区因此在 4/5 行之间反复增减。此前实现一律在 live 区**底部**加减行，于是输入框相对终端整体挪了一行，逐行差分把每一行都判成变化并逐行重画——重画进行到第一行时屏上同时存在新旧两条**顶**边框，到第三行时两条**底**边框。Apple Terminal 不支持同步输出（DECSET 2026），这些中间态会真的画到屏幕上。

修复改为按新旧帧的行对齐结果，在 live 区**顶部**用 IL/DL 增删行：终端一次原子上/下移，输入框与状态行相对屏幕纹丝不动，帧差随之缩到真正变化的那几行（常见情形是零行，一个字节都不必发）。整体平移没有更优时（例如新行确实加在底部）保持原有的底部增减，故不会比修复前更差。

同场景终端写入量由 **422KB 降至 131KB**。该缺陷自 v1.13.0 起即存在（本次已对两版分别实测确认），并非 v1.14.0 引入。

## 修复：深色终端下次要文字不再近乎不可见

状态行后缀（`· Esc 取消`、`· 缓存命中 N%`、`· 已排队 N 条`）、待办 `○` 行、权限与技能面板的说明、`/model` `/skill` `/mcp` 的项说明、diff 上下文行号、代码块语言标注、模型回复中的引用块——这些文字此前统一使用 `DARK_GRAY`。

该常量实际映射的是 **ANSI 亮黑（SGR 90）**，而 ANSI 0–15 的具体颜色由**用户终端配置文件**决定（各家从 `#333` 到 `#666` 不等），代码侧无法控制；对常见深色底 `#1e1e1e` 的对比度仅约 **2.24:1**，低于 3:1 的可读下限，深色窗口里就是「看不见」。

本版把灰色统一到 **256 色灰阶**（各家终端配置基本不改这一段，取值可控），并在调色板中固化三档层次：

| 档位 | 取值 | 对比度 | 用途 |
| --- | --- | --- | --- |
| `GRAY_TEXT` | 250 | 8.8:1 | 提示 / 空态 |
| `GRAY_INFO` | 248 | 7.0:1 | 信息行 / 引用块 |
| `GRAY_MUTED` | 244 | 4.2:1 | 装饰性最次要文字 |

模型回复中的**引用块**（`> 文字`）一并从最暗档提到 `GRAY_INFO`——它是回复正文而非界面装饰，与正文的区分交给斜体。同时修正代码块左边栏：此前使用 truecolor `rgb(120,150,200)`，而目标终端 `COLORTERM` 为空、不支持 `38;2;r;g;b`，该颜色**一直未生效**，现改为 `indexed(110)`。

## 质量

`mvn -pl springai-code-tui -am clean package -Pdist` → **1513 个用例，0 失败 0 错误**（其中 9 个需真实外部服务或 API Key 的 smoke 用例按条件跳过）。

本版新增两道回归网：

- **`ThemeContrastTest`**：反射遍历调色板的全部静态样式，断言不使用 truecolor、前景不使用 ANSI 黑/亮黑、中性色前景对背景的对比度不低于 3:1。只对中性色设亮度下限是刻意的——错误与警示色使用 ANSI 红，靠色相而非明度区分，一刀切的阈值会误伤。
- **`stream_box_smoke.py`**：真实 pty 冒烟。把应用写往终端的原始字节流按**每个游标动作**切片重放进 VT 解释器，逐刀断言屏上只有一条输入框边框、正文不丢、回合结束后边框完整，并断言流式期间不再发出 ANSI 亮黑前景。整帧采样看不到「一闪而过」的中间态，必须切到帧内部才能捕获。

两处修复均经变异实测：逐一回退后由**不同**断言为正确的理由判红，互不遮蔽。
