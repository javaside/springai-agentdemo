# v1.26.4 — 启动不再钉底：空的高窗口上半屏留空修复

在 [v1.26.3](v1.26.3.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-10-19。

## 修复：启动时窗口上半段大量空白，拖动一次窗口大小后才消失

**现象**：在又高又空的终端窗口里启动 `code-tui`，欢迎横幅堆在屏幕底部（输入框正上方），上半屏全部留空；随手拖动一次窗口大小，空白立刻消失、内容变为从顶部铺开。

**根因（两条锚定策略互相矛盾）**：纯滚动模式（[v1.23.1](v1.23.1.md) 引入）的首帧会发 `ESC[999B` 把 live 区「钉」到屏幕最底行，此后欢迎横幅经 scrollback 打印从屏幕底部往上长；而窗口 resize 的重放路径是「清屏 + 光标归顶（`ESC[H`）+ 按新宽度从第 0 行重放」——顶对齐。于是同一个界面存在两套锚定：钉底（启动）与顶对齐（resize）。窗口越高、启动时越空，钉底一侧的表现就是「上半屏空白」，resize 一次就被顶对齐重放「治好」。v1.23.1 的验证矩阵只验了「空屏钉底成立」，没有把「空高窗口首屏观感」纳入断言。

**修复（锚定启动光标处，即 Claude Code 语义）**：删除首帧 `ESC[999B` 钉底，live 区锚定在启动光标位置。纯滚动的腾行原语「底行 CRLF 滚屏」本身位置无关——CRLF 未到屏幕底行前只是光标下移、live 区随之整体下移，到顶后自然转为滚屏；scrollback 打印其余字节序列零改动，全程依旧零 `ESC[1L` 插行（不触碰 [v1.23.1](v1.23.1.md) 定案的 Terminal.app 崩溃诱因）。修复后启动与 resize 重放同为顶对齐：横幅从启动光标处向下铺，输入框紧跟内容，空白在内容下方而非上方。

### 用户可见的变化

- 空的高窗口启动：欢迎横幅从你敲命令的位置往下铺，输入框紧随其后，空隙在下方——与拖动窗口大小后的形态一致。
- 从满屏历史的提示符启动（live 区本就在底部）：行为与之前完全一致，无观感差异。
- `-c` 恢复会话：长历史同样从顶部铺起。
- 模型输出期间的滚动行为、输入法、光标带修复均不变。

## 附带：验证脚本修正（headless pty 工具链）

- `dev/terminal-stress/scroll-verify.py` 补回 docstring 一直声称的「先 println×26 预填」（v2 重写时丢失，此前一直靠首帧钉底兜底）；预填改用空白行，避免被 ghost 断言误判。
- 该脚本与新增的 `startup-anchor-verify.py` 都把 `springai-tamboui-inline-patch/target/classes` **前置**在依赖 jar 之前——原先 classpath 只含依赖 jar，会静默解析到上游 `tamboui-core 0.4.0` 自带的旧版 `InlineDisplay`（`ESC[1L` 插行实现），「零插行」断言因此失效且极难察觉（上游 jar 确实含有同名类，编译运行都不报错）。
- 新增 `dev/terminal-stress/startup-anchor-verify.py`：启动锚定契约守卫——45 行空窗下断言横幅从第 0 行铺、live 区紧随其后、字节流零 `ESC[999B`、零 `ESC[1L`、零残影。
