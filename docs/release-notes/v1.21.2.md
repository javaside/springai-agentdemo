# springai-agentdemo v1.21.2

在 [v1.21.1](v1.21.1.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版四个修复，均源自排查一份真实用户报告（附截图）："切换 model 时输入框还是会乱，按 Esc 退出选择，但上面 `/model` 等命令也越积越多；按 Esc 退出选择后，输入框都看不见了，动一下鼠标才出现输入框"。排查过程本身也有一次弯路：第一次修复是真实有效的，但验证只在开发目录里做，从没部署到用户实际在跑的已安装二进制——用户复测时看到的还是老问题。带着这个教训重新排查（直接对着用户在跑的装置验证），又找出两个独立的深层 bug。

**下载物：** 两个自包含运行包 `springai-code-tui-1.21.2-dist.tar.gz`（macOS / Linux 首选）/ `springai-code-tui-1.21.2-dist.zip`（Windows 首选），解压即用、无需构建，内容与惯例一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.21.2`**。SHA-256 校验和见文末「发布前验证」。

## 修复：`InlineDisplay` 收缩 live 区时删除起点算错，反复开关 `/model` 选择器残影堆积

`code-tui` 的界面是一块共享的「live 区」——todo 面板在最上面，`/model` 选择器/斜杠命令补全菜单在中间，输入框和状态行贴底。`InlineDisplay#resizeDisplay` 在这块区域收缩、且判定走「不整体平移」路径（`shiftRows=false`，todo 面板行数较多时会走这条路径）时，此前用 `down(newHeight)` 定位终端删除行（DL）的起点——但 `newHeight` 是「顶部稳定内容（todo 面板）+ 底部稳定内容（输入框/状态行）」两段行数之**和**，不是顶部稳定内容自己的行数。顶部有稳定内容时，这个起点会落进正在收缩的那部分内容中间，DL 从那里往下删，删掉的是「变化区域剩余部分 + 底部稳定内容」，唯独漏删变化区域最前面几行——它们从此没人再删，永远停在屏幕上。反复开关 `/model` 选择器，每次都多堆一份，正是用户截图里"`/model` 等命令越积越多"的根因。

修法：删除起点不再用高度差硬算，改为对内容逐行比对现算「顶部这次真的没变的行数」，删除位置和之后重新对齐内部快照（新增 `InlinePatch.realignWithStablePrefix`）统一用这个数——两处算错或算漏一处，内部快照和终端实际内容就会对不上，下一帧的差分要么白画、要么漏画。

## 修复：`/model` 选择器无行数上限，导致 live 区超出终端高度后输入框消失

模型目录现在有 20 个，`/model` 选择器此前把整份目录不加节制地铺开渲染。加上 todo 面板，live 区经常长到超过终端实际可见高度。这时终端对光标的相对移动（`ESC[nA`/`ESC[nB`）会被物理边界截断（不可能移到屏幕外），但 `InlineDisplay` 的位置计算全程假设移动量总能足额生效——一旦被截断，后续所有相对定位全部错位。这正是用户截图里第二个现象的根因：按 Esc 关闭选择器后输入框整段消失，要等一次不相关的事件（比如挪一下鼠标触发终端重绘）才会被带回来。

修法：照抄 `/skill` 选择器已有的窗口化做法（`SKILL_PICKER_CAP`），给 `/model` 选择器新增 `MODEL_PICKER_CAP = 10`——最多同时显示 10 项，以当前选中项为中心自动滚动，超出部分在面板底部标注「显示 X-Y / 共 N 个模型」。这从根上避免了 live 区超出终端高度的场景，而不是去修补「超出之后怎么办」。

## 修复：斜杠命令补全菜单收紧过滤词时，「顶部真没变行数」的判断被巧合内容骗过

上一条修复用「内容比对」现算顶部稳定行数，这个算法本身有个隐藏漏洞：贪心比对只看"这一行文字是否碰巧相同"，分不清"这是没变的稳定面板"还是"变化区域第一行恰好和上一帧对应位置长得一样"。斜杠命令补全菜单收紧过滤词时（`/` → `/m` → `/model`）就会撞上后者——最靠前的匹配项全程都是 `/model`，那一行文字在收紧前后逐字节相同，贪心因此会把它多算进"顶部稳定内容"，删除起点多算一行，真正该删的那一行反而漏删。表现为反复输入 `/model` 后界面卡死、输入框里残留一行没提交的文字（且不会随时间自愈）。

修法：贪心找到候选边界后，加一道尾部整体校验——候选边界之后剩下的内容必须整体经得起同一个位移量核验（即确实是终端 DL 操作物理移动过的那部分），验不过就回退到更短的、真正只覆盖稳定面板的前缀，不能拿巧合当真。

## 修复：`/continue` 续跑不再清空刚恢复/中断前的 todo 面板

`-c` 恢复会话时正确重建了 todo 面板（v1.21.1），但一按 `/continue` 面板又立刻消失，像是主 agent 不再用 TodoWrite 了。根因：`ConversationState.onTurnStarted` 在每个新回合最开始都无条件清空 todo 面板（新回合 = 新计划，用完即走），且是同步执行、抢在模型还没来得及做任何事之前——而 `/continue` 的提示词只让模型"回顾"计划、委派子 agent 续跑，没有要求它立刻重调一次 TodoWrite 把面板点亮，面板因此要等到模型自己因某个任务状态变化才会重新出现，中间就是那段空窗。这直接抵消了刚发布的 `-c` 恢复面板修复的意义。

修法：`/continue` 续的是同一份计划，不是新计划。新增 `ConversationState.preserveTodoOnNextTurn()` 一次性标记，`/continue` 派发前调用，`onTurnStarted` 消费到标记时跳过这次清空（消费后自动复位，后续回合恢复默认清空）。只护 todo，不护任务面板（子 agent 状态）：谁在跑天然回合级，不管是不是 `/continue` 都该清。

## 测试

- **`InlineDisplay` 删除起点修复**：`InlineDisplayDiffTest` 新增单测钉住 DL 必须发在正确行（既有 30 余个单测全部仍绿——均未触发过 `shiftRows=false` 分支，故不受影响）。
- **`/model` 选择器窗口化**：既有 `CodeTuiViewModelMemoryTest`/`CodeTuiViewThinkingSettingsTest` 用的测试模型列表本就小于新上限，窗口化对它们是无操作变化，回归零成本。
- **贪心比对巧合内容修复**：无独立单测（此类跨帧终端语义问题单测天然测不到），由下方 PTY 冒烟脚本覆盖。
- **`/continue` 不清空 todo 面板**：`ConversationStateTest` 新增 3 例（保留生效、一次性消费、任务面板仍清空）；`CodeTuiViewContinueDigestTest` 新增 1 例钉住 `/continue` 确实调用了新方法。
- **端到端**：新增 PTY 实机冒烟 `model_picker_smoke.py`（本地 SSE 桩起假模型触发 TodoWrite，20 行小窗口逼真实终端贴底——不逼窄的话 live 区长高只是往空白里长，问题不会现），复现用户截图场景并验证反复开关 5 轮全程零残影、输入框全程可见。所有改动均按 revert-confirm-red / restore-confirm-green 的变异测试纪律逐一验证，其中 `/model` 选择器三处修复额外对着用户实际在跑的已安装二进制直接验证，不只是本地构建。
- 两个模块全部单测（`springai-tamboui-inline-patch` 30 余个、`springai-code-tui` 2053 个）与 `background_smoke.py`（后台子 agent 派发、⏱ 面板、自动续回合、终止、`/continue` 摘要拼接五个场景）均通过。

## 升级说明

**无配置变更，无破坏性变更。** 直接替换运行包即可。升级时请先退出旧进程，再替换文件并重新启动（`jar` 走 Java 类加载，替换文件后必须重启才生效——这也是本版问题排查过程中的一个教训：验证修复必须对着用户实际启动的那个进程/安装目录，不能想当然认为"代码改了就等于用户那边生效了"）。

- `/model` 选择器现在最多同时显示 10 项、超出会分页滚动并显示「显示 X-Y / 共 N 个模型」——选择/切换操作不变，只是不再一次性铺开全部选项。
- 受影响场景：todo 面板较长（尤其是子 agent 委派较多的长会话）时反复开关 `/model` 选择器，此前会累积残影且输入框可能短暂消失，现在两个现象都不再出现；`-c` 恢复会话后用 `/continue` 续跑，todo 面板现在会保持可见，不再有一段空窗期。
