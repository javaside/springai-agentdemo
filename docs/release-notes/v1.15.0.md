# springai-agentdemo v1.15.0

在 [v1.14.1](v1.14.1.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版聚焦**长会话的自动压缩**与**子 agent 的瞬态故障韧性**：自动压缩不再固定切块串行，改为先乐观整段摘要（理想情形一次调用完成，此前约需 8 次）；窗口配置虚高时靠真实失败校准出该模型的真实容量，跨压缩记忆、越用越准。子 agent 的重试判定对齐生产日志实测的四类瞬态故障，此前重试层一天 0 次触发、失败全冒泡。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.15.0-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.15.0-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.15.0`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.14.1 的变化。

## 新功能：自动压缩乐观全量摘要 + 区间校准

此前自动压缩（`/compact` 之外的会话内触发）固定按 `min(64k, 窗口/8)` 切块、逐块串行摘要再拼接——窗口配置正确时这是纯粹的浪费：一份 15 万 token 的历史被切成约 8 次模型调用，多耗约 7 次请求与分钟级时延；窗口配置虚高时又会整段发送、必然超限失败。

本版把压缩策略改为**先乐观后校准**，并让窗口配置错的时候系统自己学对：

- **乐观全量**：压缩先整段送摘要模型（一次调用）。成功即完成——大多数窗口配置正确的场景从此从约 8 次调用降到 **1 次**。
- **超限失败学习容量**：整段超限时按响应内容分派——带具体数字的报错（如 `120000 tokens > 60000 maximum`）**数字锚定**，一步算出真实窗口并直接按它切块，无试探请求；不带数字的报错用**前缀减半探测**（结果仅学习容量、不入摘要），从失败量逐次减半。
- **区间记忆**：按 `provider:model` 维护 knownGood / knownBad 区间（进程内共享、不持久化）。压缩用得越多，对该模型真实容量的估计越准；区间**短路**保证绝不重发注定失败的请求（失败量以下直接按已知安全预算切块）。
- **安全阀与硬上限**：切块预算低于 16k 或块数超过 8 时放弃切块、直接本地摘要兜底；全程模型调用上限 **20 次**，任何失败最终落到不依赖模型的本地纯文本摘要，压缩永不失败、也永不失控。
- **摘要输出上限**：摘要请求声明「8000 token 以内」并以 `maxTokens=8192` 硬截断双保险，杜绝摘要模型自行膨胀把省下的空间又吃回去。

配套：压缩装配改为单次模型快照取窗口（并发 `/model` 切换时不再出现「A 家模型配 B 家窗口」的交错），auto/manual 两条压缩策略共享同一份校准状态（校准是模型的属性，不是策略实例的属性）。

## 新功能：内置清单支持 glm-5.3

`ZhipuProvider` 内置清单置入 **glm-5.3** 为默认旗舰（glm-5.2 降为上代），thinking 能力按官方模型卡对齐：**仅支持开启、不可禁用**，`reasoning_effort` 取 low / high / max（默认 max）。`ModelContextWindows` 补 `zhipu:glm-5.3` 的 1M 窗口条目，`opencode-go` 网关同名回退复用原厂条目；`config.env.example` 与使用指南同步。

上下文窗口是本版压缩校准的输入，glm-5.3 的 1M 条目让新压缩策略对旗舰模型直接按真实窗口工作。

## 修复：子 agent 重试对齐真实瞬态故障

生产日志（1.14.0 运行目录，2026-08-17）显示子 agent 失败 10 次而重试层 **0 次触发**：`shouldRetry` 只认 `InvalidDataException` / `No content to map`，匹配不到网关实际抛出的故障——`OpenAIIoException`（OkHttp 断连）、流中途 EOF、上游限流与 5xx。失败后主 agent 只能整包重派子 agent（上下文从零重建），是任务延期的直接机制。

本版扩容四类瞬态判据（cause 链逐层判断，取消信号优先不变）：IOException 家族与 `*IoException` 类名后缀、`EOF reached while reading`、限流（`rate limit` / 429）、5xx；重试间隔改为指数退避。

## 质量

`mvn -pl springai-code-tui -am clean package -Pdist` → **1551 个用例，0 失败 0 错误**（其中 9 个需真实外部服务或 API Key 的 smoke 用例按条件跳过）。

本版新增三组回归网：

- **`CalibrationStateTest`**（6 例）：区间单调性（knownGood 只涨、knownBad 只降）、矛盾证据时收缩下界并撤销证明、共享状态跨实例读取。
- **`BoundedSummarizationCalibrationTest`**（11 例）：策略级全路径——乐观成功、数字锚定、减半探测、knownBad 短路、中间区带收紧、非超限异常不学习、安全阀两道（预算 16k 下限 / 块数 8 上限）、全局调用恰第 20 次掐断、切块中途失败保留学习、共享校准零试探。
- **`SummarizerOverflowTest`**（9 例）：超限分类（带数字 / 不带数字 / 无关异常）与窗口数字提取，覆盖 OpenAI / Anthropic / Zhipu 风格报错文本。

压缩策略核心路径经变异实测：逐一回退乐观/锚定/短路分支后由不同断言判红，互不遮蔽。子 agent 重试修复的判定矩阵另有设计文档存档（`docs/superpowers/specs/2026-08-18-subagent-retry-transient-expansion-design.md`）。
