# v1.22.0 — 限额感知重试 + 大粘贴三件套 + MCP 运行期重载

在 [v1.21.7](v1.21.7.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-09-23。

本版五件事：**① 智谱 Coding Plan 限额感知重试**——撞上 5 小时/7 天滚动限额时不再
「退避一分钟耗尽预算、回合失败、人肉重发」，而是识别 429 业务码、解析 message 里内嵌的
重置时刻，回合挂起、界面显示倒计时，睡到重置点**自动续跑**（Esc 随时可取消）。
**② 大粘贴三件套**——贴几百 KB 日志不再「被拆成碎片、日志里的换行变 Enter 触发分批
自动发送、输入框把整个界面顶飞」：传输层放宽粘贴读超时、输入框把超长粘贴折叠成
`[TEXT1]`、回显只显示前两行+全文行数。**③ MCP 配置运行期重载**——改 `mcp.json` 不用
重启进程，`/reload` 或 `/mcp` 面板按 `r` 即热生效。**④ `-h/--help` 启动参数**——
没配任何 API key 的新机器也能先看用法。**⑤ 仓库基础设施**——版权行统一署名、
发版脚本支持 Gitee 镜像。

## 功能：智谱 Coding Plan 限额感知重试（等到重置时刻自动续跑）

### 问题

智谱 GLM Coding Plan 有**滚动 5 小时**与**滚动 7 天**两套使用限额，撞上即返回
HTTP 429（业务码 1308/1310/1316-1321），且**重置时刻只内嵌在中文 message 文本里**
（「您的限额将在 `2026-09-22 15:30:00` 重置」），无结构化字段、无专用响应头。

此前的行为：429 被判为瞬态错误走指数退避——但退避封顶 30 秒，对「几小时后重置」的
限额窗口，主链路约 1 分钟即耗尽重试预算，回合以失败告终。用户要么守着电脑手动重发，
要么放弃这轮任务。深夜挂机跑长任务时这尤其致命：限额在凌晨两点撞上，重置在五点，
旧版会在 02:01 就把回合杀掉。

### 行为

现在：

- **识别**：`QuotaLimitDetector` 沿 cause 链认出 429 + 智谱限额业务码（1308/1310/
  1316-1321，业务码字符串缺失时按 message 双关键词兜底），并从 message 解析出重置时刻。
- **等待**：回合挂起（不是失败），输出区插入提示行
  `⏳ 限额等待：将于 15:30 自动重试（Esc 取消）`，状态栏持续显示剩余倒计时
  （`45s` / `2m30s` / `3h5m`，渲染帧现算，到点前一刻显示「即将重试」）。
- **续跑**：睡到重置时刻自动重试。重试边界处理周全：mid-stream（已下发部分内容后）
  撞限额的，已下发内容不重放、从断点续跑。
- **Esc 取消**：等待期间随时可取消，包括串行子 agent 的等待（本版补齐了串行子 agent
  执行线程的登记与 interrupt 短板——此前它的等待无法被打断）。
- **不挤占普通重试预算**：限额等待的次数从耗尽判定中扣减（reactor 的重试计数无法
  重置，只能按次数做偏移），网络抖动这类普通瞬态错误的预算一分不让。

三条重试路径（L1 流式透明重试 / L2 回合级续跑 / 子 agent 阻塞重试）**全部覆盖**——
判据、等待时长、预算豁免全部收在 `RetryPolicy` 单一真相源里，三条路径因共同委托它
自动获益。

### 不等的错误（刻意）

近邻错误 1113（账户欠费）、1309（套餐过期）、1311（模型权限）**不在等待集合内**：
它们等到天亮也不会自愈，等它们是浪费——保持「429 瞬态、有限重试后失败」的现有行为。
反例与正例一样有真机 429 payload 回归钉守着（1113 反例、1308 Coding Plan 5h 正例）。

## 功能：大粘贴三件套（传输层 + 输入框 + 回显）

一个用户报告的三连症状：贴一段几百 KB 的日志，**① 内容被拆得七零八落**（部分内容
根本没进输入框）、**② 日志里的换行变成 Enter**、输入框里的片段被「贴入即分批自动
发送」、**③ 输入框随粘贴行数无限增高**，把整个界面顶出屏幕。三件事各有各的根因，
本版各修各的：

### ① 传输层：粘贴读超时放宽（`springai-tamboui-inline-patch` shadow `EventParser`）

上游 TamboUI 0.4.0 对括号粘贴内容逐字符 `read(50ms)`，**单次超时立即放弃**。大粘贴时
终端分块灌 pty（macOS pty 输入队列仅 ~1KB），块间间隙一旦超过 50ms，粘贴事件被提前
掐断，剩余字节回落到普通按键解析——`\n` 变 Enter，正是「贴入即分批自动发送」的根源。

shadow 类（与 `InlineTuiRunner` 同机制，靠 Class-Path 顺序先于上游 jar 加载）把语义
改为**累计静默 500ms 才放弃**（每次收到数据重置计时，人手敲不出 `ESC[200~` 起始标记，
无副作用；EOF 仍立即放弃）；同时原始流轮询间隔从 50ms 降到 1ms——轮询间隔即吞吐上限，
50ms 只有 20KB/s（4MB 粘贴要 223 秒），1ms 约 1MB/s。

### ② 输入框：超长粘贴折叠成 `[TEXT1]`

超过 **400 字符或 12 行**的粘贴，输入框里只插一个 `[TEXTn]` 占位符（与 `[IMAGEn]`
图片占位符同一套路，编号随登记自增），全文登记在侧、**提交时展开还原**发给模型——
同 Claude Code 的 pasted text 折叠。细节都替你守住了：

- 附件行提示 `⏎ 已折叠 2 段长文本（共约 12.3K 字）`——折叠静默发生的话，用户不会
  知道将发出去的是几十 KB；
- `/queue` 排队在入队前展开（出队发送时映射已随草稿复位，占位符将永远等不到展开）；
- Esc 取消回合后回填的插话是**展开后**的全文，会重新折叠登记——取消一次不该把几千
  行日志灌回输入框；
- 粘贴文本先归一 `CRLF`/裸 `CR` 为 `LF`（复制自 Windows 风格输出的日志常带 `CR`，
  否则以不可见字符落进输入框、原样发给模型）；
- 用户手打的 `[TEXT2]`（未登记的编号）是普通文本，原样保留。

### ③ 回显折叠：scrollback 与重开会话同规则

发给模型的是全文，但**显示**不照登：实时回显（`onUserMessage`）与重开会话回放
（`HistoryReplay`）对超长用户消息统一折叠为**前 2 行**（单行超长再按 160 字符截断）
加尾行 `…（已折叠，全文 312 行）`——行数必须是真的，用户得知道被折掉的是 30 行还是
3000 行。只影响显示，永不改发给模型的文本。

## 功能：MCP 配置运行期重载

改 `mcp.json`（全局层或项目层）从此不用重启进程：

- 两个入口：`/reload` 命令（技能照扫 + MCP）与 `/mcp` 面板按 `r`；完成后打摘要
  `新增 X · 移除 Y · 重连 Z`。
- 按名字 diff 增量生效：**新增**条目后台连接立即可用、**删除**条目摘工具关连接、
  **同名参数变更**换新连接重连、**未变**条目原样保留（已连接的不闪断）。
- `enabled` 意图以文件为准（面板里的临时开关不覆盖重载）。
- 回合忙碌时跳过 MCP 部分并明确提示——运行中摘工具会撞上在飞调用。

写回守卫同步重构为普适两道（closed / 条目已被 reload 替换移出表），杜绝旧配置的
孤儿 client 冒充新配置产物。

## 小功能：`-h/--help` 启动参数

`main` 第一件事判定 `-h/--help`，打印中文用法后直接退出——判定早于 API key 检测，
**没配任何 key 的新机器也能先看帮助**。整串精确匹配，`-help`/`--h`/`--helpx` 等
前缀拼写不误判。帮助文本覆盖全部 4 个启动参数，并有契约测试钉住「帮助不撒谎」
（新增启动参数时两边必须同步）。
