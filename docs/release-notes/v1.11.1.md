# springai-agentdemo v1.11.1

在 [v1.11.0](v1.11.0.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版修复两处：**OpenCode Go 网关同名模型的上下文窗口误判**（导致自动压缩过早、频繁触发），以及**构建/打包命令文档缺 `-am` 与 `-Dsurefire.failIfNoSpecifiedTests` 导致的依赖解析失败**。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.11.1-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.11.1-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.11.1`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.11.0 的变化。

## 修复：网关同名模型上下文窗口误判，自动压缩不再过早触发

OpenCode Go 聚合网关提供的模型与各家原厂模型**同名**（如 `deepseek-v4-pro`）。上下文窗口解析器 `ModelContextWindows` 此前只认原厂 provider 键（如 `deepseek:deepseek-v4-pro`），对 `opencode-go:deepseek-v4-pro` 精确命中失败后直接落到 **128K 保守兜底**——而该模型真实窗口是 **1M**。

后果是自动压缩阈值被算成 `0.7 × 128K ≈ 89.6K`（真实窗口的 **~9%**），压缩目标则进一步压到约 54K。于是新会话读几份文档、一个回合多一点，就会跨过触发线；压完回到 54K、很快又涨回去，**反复触发**——表现为「刚开一个新会话没多久就自动压缩」。

本版在精确键 miss 后增加**按 modelId 的同名回退**：

- 先查显式覆盖（`CODETUI_CONTEXT_WINDOWS`），再查内置能力表，命中同名原厂条目即复用其窗口；
- 多个同名条目声明的窗口值**互相矛盾时不猜**，落保守兜底（网关给的可能不是同一模型）；
- 网关独有的模型（如 `glm-5.2`、`kimi-k3`）仍按未知模型保守兜底，行为不变。

新增 4 个回归测试钉住：网关同名命中、显式 override 优先、冲突不猜、未知网关仍兜底。

## 文档修正：构建与打包命令可原样运行

`CONTRIBUTING.md` 与 `springai-code-tui/README.md` 的构建命令此前存在两处会让「复制即跑」失败的问题：

- **缺 `-am`**：`springai-code-tui` 依赖不发布到远程仓库的兄弟模块 `springai-tamboui-inline-patch`，不带 `-am` 时本地 `~/.m2` 未装同版本就会报依赖解析失败；
- **单类命令缺 `-Dsurefire.failIfNoSpecifiedTests=false`**：`-Dtest` 是全局系统属性，`-am` 拉进 reactor 的兄弟模块用它匹配不到测试时，surefire 默认报 `No tests matching pattern` 而中断整个构建。

该参数只放宽「`-Dtest` 模式没有匹配到任何测试」这一种错误，**不吞**断言失败、编译失败、运行时异常（本次发布前已变异实测确认）。文档同时更正了此前对它的误导描述。
