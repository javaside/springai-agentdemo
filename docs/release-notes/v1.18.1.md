# springai-agentdemo v1.18.1

在 [v1.18.0](v1.18.0.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版修复 DeepSeek 视觉输入链路三个会话级可靠性问题：有工具历史时图片因消息下标错位而静默丢失、项目外图片 Read 的二进制 hexdump 进入模型上下文、以及同一张 artifacts 图片经「用户附件」和 Read 两条路径产生不同 id。

**下载物为两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.18.1-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.18.1-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.18.1`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.18.0 的变化。

## 修复：DeepSeek 在工具历史后也能真正收到图片

此前图片字节经 `DeepSeekThinkingChatModel` 注册、在 HTTP 请求改写器中再按消息下标取回并写成 `image_url` / `file` 块。但 spring-ai-deepseek 会把一条 `ToolResponseMessage` 中的多条工具响应展开成多条 HTTP `role=tool` 消息：请求序列化后的绝对下标不再等于内存 `Prompt` 中的消息下标。

因此，只要用户贴图前存在多响应工具调用，注册与消费的 key 就错位；模型只看见 `[file reference]` 文本，实际没有收到图片，且整个过程 fail-open、不报错。

本版统一改用 **user 消息序号 + media 序号** 关联图片：每条 `UserMessage` 序列化后仍一一对应一条 `role=user` 消息，且相对顺序不受工具响应展开影响。带图 user 之前有任意数量或任意条数的工具响应，图片都能稳定注入对应请求。

---

## 修复：项目外图片 Read 不再把 PNG/PDF 二进制文本送进模型

模型 Read `~/Downloads/xxx.png` 等项目外路径时，旧路径因安全包含校验无法把原始路径写进引用块；Read 工具返回的 PNG hexdump 又常被当作普通文本，最终大段原始字节进入模型上下文。

现在对于已确认存在的项目外非文本文件：

- 成功时复制进 `.codetui/artifacts/`，返回 root 内的结构化引用；原绝对路径不会写入会话。
- artifacts 外置失败（目录不可写、磁盘满、文件消失等）时 **fail-closed**，只返回“内容已从会话移除”的占位文本，绝不回退原始 hexdump 或字节。
- 普通文本文件、无法反查源路径的普通工具输出维持原有行为。

---

## 修复：同一张 artifacts 图片保持同一个 id

项目外用户附件复制进 artifacts 时使用内容 SHA-256；此前模型随后 Read 该副本时改按路径计算 SHA-256，造成同一张图片有两个 `id`，影响模型判断“是否是刚才那张图”和视觉引用去重。

本版识别 artifacts 内容寻址文件名，Read 该副本时沿用内容哈希；项目内普通源文件仍保留稳定的路径哈希语义。

- `mvn -pl springai-code-tui test` → **Tests run: 1620, Failures: 0, Errors: 0, Skipped: 10**（10 个 skipped 为环境变量门控的联网/真机探针）

新增回归覆盖：

- 多响应工具历史展开后，带图 user 仍能注入 image block；并覆盖多图顺序。

- 外置失败时 fail-closed 移除二进制内容。
- artifacts 副本 Read 与用户附件使用相同内容哈希 id。
