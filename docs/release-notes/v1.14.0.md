# springai-agentdemo v1.14.0

在 [v1.13.0](v1.13.0.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版主题是 **流式调用不再无限卡住，缓存状态更易扫读**：全部 provider 的模型流增加首包及相邻数据块空闲超时，默认 300 秒无新数据时主动结束并恢复可提交状态；缓存命中率在思考和工具运行期间继续可见；窄终端优先保留模型与动态状态，并将缓存命中百分比值单独高亮。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.14.0-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.14.0-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.14.0`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.13.0 的变化。

---

## 新功能：LLM 流式空闲超时保护

全部六家 provider 的流式调用统一增加空闲超时：首个响应或任意两个响应数据块之间默认超过 300 秒无新数据时，当前调用会主动结束，不再无限停在「思考中」或工具运行状态。错误经现有回合收尾路径显示后，输入框恢复可提交。

超时复用 `CODETUI_LLM_READ_TIMEOUT_SECONDS`，合法范围仍为 10–3600 秒。上游已经给出明确超时错误时保留原始信息；本地检测到空闲时会提示实际等待秒数及配置名。超时前已收到的 usage 仍会在错误传播前提交，缓存命中统计不丢失。

---

## 改进：忙碌态继续显示缓存命中率

`THINKING` 与 `RUNNING_TOOL` 状态行现在继续显示当前会话累计的 `缓存命中 N%`，无需等待回到空闲态。忙碌态不重复显示上下文占比，以控制状态行长度；长工具摘要会先收缩，为缓存命中率、权限模式标签和 `Esc 取消` 让出空间。

---

## 改进：窄终端状态优先级与百分比高亮

空闲状态栏在空间不足时按「模型及动态状态 → `Enter 发送` → 次要帮助组」保留内容。`/model`、`Esc`、`Ctrl+C` 三项帮助会整组隐藏，非默认权限模式标签也计入宽度预算，避免上下文和缓存命中率再次被挤出 80 列终端。

`IDLE`、`THINKING`、`RUNNING_TOOL` 中仅缓存命中率的完整百分比值 `N%` 使用冷薄荷色加粗；`缓存命中` 标签、分隔符、上下文百分比和 `/context` 报告保持原样。
