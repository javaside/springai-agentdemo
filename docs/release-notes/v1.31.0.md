# v1.31.0 — 平台大版本（Spring AI 2.1.0 + TamboUI 0.7.0）与五家新模型

在 [v1.30.0](v1.30.0.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-11-21。

本版是一次「平台双升级 + 模型清单刷新」：底层框架 Spring AI 2.0.1→2.1.0、终端 UI 库
TamboUI 0.4.0→0.7.0，六家 provider 里三家（Anthropic / OpenAI / 聚合网关沿线）模型清单更新。
所有升级均按「spec → 分支 → 全量测试 → 真机冒烟 → 整支终审」流程执行，过程记录见
`docs/superpowers/specs/`（2026-11-21 三份升级设计文档）。

## 一、Spring AI 2.0.1 → 2.1.0 —— 六处版本联动与 session API 迁移

**版本矩阵**（全部经 Maven Central 实测核对）：spring-ai 2.1.0、Spring Boot 4.0.7→4.2.0、
openai-java-okhttp 4.49.0→4.101.0、anthropic-java-okhttp 2.52.0→**3.8.0（跨大版本）**、
spring-ai-agent-utils 0.13.0→0.14.0、会话记忆从社区版 `spring-ai-session-management:0.5.0`
切换到官方收编坐标 `org.springframework.ai:spring-ai-session(-advisor)`。

**官方 session API 迁移**（本版最大改动面）：2.1.0 官方把压缩改为 append-only（boundary +
summary 事件追加、`EventFilter.active()` 视图遮蔽被覆盖历史），`SessionRepository` 不再提供
历史改写入口。但本项目的取消回滚 / 裁悬空 tool_calls / 插话补历史 / goal fold 是**修复性
改写**，没有 append 语义可用——新增自有 `HistoryRewritingRepository` 接口承载这批能力，
`FileSessionRepository` 同时实现它与官方新接口（乐观锁 `appendEvents`、run-based
`DiffResult`、`CompactionResult` 六参、`SessionEvent` 去 branch、`Session` 去 userId）。
会话文件格式向前兼容（`eventType/payload` 新分支承载压缩 boundary，旧文件零迁移读取）。

**升级夹带的行为契约变化**（18 个钉行为断言逐条归因后校准，零真回归）：流式 chunk 的
`getText()` 永不为 null；官方 advisor 不再兜底落库空 user（重放/续跑轮不再重复落问题文本）；
`after()` 过滤无内容 reply；压缩产物口径为 covered/pinned/preserved + summary。

**升级终审修复（Critical）**：官方 `SessionEvent.getMessage()` 对非 MESSAGE 事件（压缩
boundary）抛 `IllegalStateException`——首次压缩后每个回合的整日志消费点全炸，最重是
**重启后整个会话文件被当损坏丢弃**（红测试复现）。修复为全消费点 `hasMessage()` 守卫透传；
含 boundary 的日志跳过事件折叠（折叠会毁掉 boundary payload 的 id 引用，活跃视图会只剩
summary）。另修 `/context` 改读活跃视图（append-only 下整日志口径只增不减已失真）。

**DeepSeek 视觉链路前提核验**：官方 2.1.0 的 DeepSeek 序列化仍忽略 media、`ToolResponse`
仍 flatMap 展开——HTTP 层视觉改写器（图片内联注入）与 `stream_options` 注入全部安全，
本地 mock 探针实证请求体像素无损。附带收益：官方现在回放 `reasoning_content`，顺带修复了
opencode-go 网关思考模式 400 的历史遗留（该网关**要求**续轮回传此字段，2.0.x 不回放才炸）。

**真机冒烟**：DeepSeek vision/websearch/spike（续跑 + 缓存命中）全绿；zhipu 颜色误认经
mock 探针（像素纯蓝无损送达）+ main（2.0.1）基线同红双证据，归因为智谱服务端近期劣化，
非升级回归。Anthropic 3.x Bearer 认证路径字节码已核（官方端点兼容），带 key 实调留待用户
环境验证。

## 二、TamboUI 0.4.0 → 0.7.0 —— 三类 shadow 分档 rebase

**升级收益**：安全修复 GHSA-5m5f-4gqv-8c29（0.6.0，OSC 8 超链接控制字符注入——code-tui
每天渲染模型输出的 markdown，真实命中）；CJK/i18n 加固（表格对齐、emoji 混排、换行）；
渲染管线 2.1× 提速；输入解码修复一票（#611 ESC 前缀 Alt、#517 错误解码序列、#481 单键多次
触发）；X10 鼠标与 Kitty protocol 解码能力。

**分档 rebase 策略**（inline-patch 兼容层，详见 spec）：
- `Buffer`：0.7 底座（diff 走 run-based 协议）+ 组合序列宽度定制全保留——上游 0.7 仍无
  `combiningSequenceLength` 方案，keycap 2 列布格 / C1 替换 / TerminalWidth 口径原样；
- `EventParser`：0.7 底座全量 rebase（Kitty/X10 与解码修复全拿到）+ 粘贴快速通道整体移植
  （静默预算 500ms / OVERSHOOT 溢出回灌 / BacklogBackend——多文件拖拽根治行为零回退）；
- `InlineTuiRunner`：**最小 rebase**——仅吸收 `TickEvent.of(long)` API 破坏，AsyncPtyWriter
  防卡死定制主体保持 0.4 基线，Kitty 运行时启用/TickTimer/windowTitle 刻意不吸收（与定制
  深度交织，风险不成比例；后续如需在 0.7 shadow 基线上增量开启）。

整支终审（0 Critical / 6 Important / 8 Minor）修复了全部 Important：rebase 噪声丢失的
glyph 驻留（边框 diff 恒等快路径）、两个 shadow 横幅与基线表述（下次升级的 diff 锚点）、
jline provided 钉版按自订协议对齐 3.30.17（javap 验证反射链字段仍在）。

**验证矩阵**：patch 126/126（粘贴/拖拽/宽度钉守）→ 七模块编译 → 全量 2574/2574 →
pty 冒烟本地 **14/14 PASS**（渲染核心六项在终审修复后二次重跑）+ 顺手修复两个冒烟脚本
腐化（`deepseek-v4-flash` 改名残留、`model.json` 新格式断言——「冒烟不进 CI 会腐化」的
又一次实证）。
