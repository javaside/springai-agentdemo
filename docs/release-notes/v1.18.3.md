# springai-agentdemo v1.18.3

在 [v1.18.2](v1.18.2.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版根治「模型输出期间打字卡死、macOS Terminal.app 整个崩溃」——根因是每帧 pty 写入限速限错了单位（限的是逻辑行数，而真正压终端的是折行后的物理行数），且「窗口正在输出」这条主路径根本没接上限速。同时把 `codetui.agent` 顶层 88 个类按功能拆进 10 个子包，并给全部 17 个 main 包补上 `package-info`。重构部分不含任何方法体改动，行为无变化。

**下载物为两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.18.3-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.18.3-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.18.3`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.18.2 的变化。

## 修复：输出期打字卡死与终端崩溃

同一个限速缺陷有两处漏网，都只有改用物理行计数才看得见：

- 每帧额度 300 数的是逻辑 `OutputLine` 条数。一条正文经折行、一条 diff 经展开，都会变成十几到上百个物理行——实测「限 300 条」的长正文实际写出 **4500 行**。
- 流式输出走的是另一条取行路径，它**完全没接限速**。而「窗口正在输出」正是走这条——实测一帧灌 **5000 行**。

后果是两条独立的：渲染线程在同一趟里做 markdown 解析、语法高亮、折行和 `println`，一帧几千行会占住它数百毫秒，这期间所有按键排队——用户感知就是「输出的时候打字卡死」；而几百 KB 的 pty 突发又会把 macOS Terminal.app 推进它自身的 use-after-free，崩溃栈落在输入法的 `setMarkedText:` → `selectedRange`，整个终端窗口关闭。

改法是把计数点挪到 sink 出口——所有 `println` 的唯一必经之路，折行恰好就发生在那里——预算按真实写出的行数扣减：待打内容改为单条取用，流式按剩余预算取用，本帧打不完的原样退回缓冲区头部，下一帧接着打。每帧写入从 5000 / 4500 行收敛到 **300 行**，不足 300 行的正常输出行为逐字节不变，多帧之间不丢行、首尾顺序不变。

## 重构：agent 域按功能分包

`codetui.agent` 此前是一个 88 个类的平铺包。本版按功能把它拆成 10 个新子包，与 4 个既有子包（`media` / `permission` / `background` / `thinking`）并列：

| 子包 | 职责 |
| --- | --- |
| `llm` | provider 接入（6 家）与 ChatModel 装饰链 |
| `seam` | CodingAgent ↔ UI 的唯一接缝（事件、提交、三种模态请求） |
| `tools` | ToolCallback 装饰链与内置工具 |
| `mcp` | MCP 客户端、配置读写与传输 |
| `session` | 会话持久化与 token 记账 |
| `compaction` | 上下文压缩策略 |
| `subagent` | 子 agent 装载与执行 |
| `skill` | 技能发现与热重载 |
| `prompt` | 系统提示片段加载 |
| `interjection` | 回合中插话 |

顶层只留下 `CodingAgent`（回合编排）与 `AgentTools`（工具集装配）两个装配类。

重构纪律是「纯位置调整」：不改任何方法体、不重命名任何类，允许的改动只有 `package` 行、`import` 行、可见性修饰符和新增注释。分 10 次提交，每次搬一个包、独立编译测试通过后才提交。

跨包装配需要放宽可见性的 35 处成员逐一核对过调用方（全部确有跨包引用，无冗余提权），并在各自 javadoc 里标注「内部类型：升 public 仅为跨包装配，勿在 agent 包外依赖」。

已知遗留、已写进 `package-info` 与清理清单的两条包循环：`agent ↔ agent.mcp`（`AgentTools.testEngine` 测试工厂）与 `codetui ↔ agent.mcp`（`McpClientManager` 取 `AppInfo` 版本号作 MCP 客户端标识）。

**对使用者无任何影响**（无配置、无行为、无命令变化）。对读代码或二次开发的人：`codetui.agent.*` 下类的完全限定名变了，`git log --follow` 可追溯搬迁前历史。

## 文档：17 个 main 包补齐 package-info

模块根、`agent`、`agent` 的 14 个子包与 `ui`，共 17 个包各写一份 `package-info`：包里装什么、为什么这么分、依赖方向指向哪里，以及那些只能从设计意图里看出、看代码看不出的约束（例如 `ModalRequest` 的 sealed 子类型为何必须与接口同包、`PermissionRequest` 为何放 `seam` 而不放 `permission`）。

复核这批注释时发现并修正了 6 处与代码不符的描述：`ui` 与模块根声称「ui 不 import Spring AI 类型」，实际 `-c` 历史回放要直接吃会话仓库的 `List<Message>`（现已改为显式列出这两处例外并标注「现状而非目标」）；`media` 的消费方列表列了两个并不引用它的包、漏了两个真在引用的；`llm` 把一个 `StreamAdvisor` 数成了 ChatModel 装饰器，又在同一句里既称自己「叶子级」又列出 3 个依赖；`session` 漏了 `ui`；`mcp` 只记了两条包循环中的一条。

## 质量

发布前验证：

- `mvn -pl springai-code-tui -am clean package -Pdist` → **Tests run: 1630, Failures: 0, Errors: 0, Skipped: 10**（10 个 skipped 为环境变量门控的联网/真机探针），两个发布包生成成功。
- `mvn -pl springai-code-tui javadoc:javadoc` → **0 error / 0 warning**（doclint 全开）。
- 重构区间全量 diff 复核：除可见性修饰符与方法体内旧包名→新包名的重指外，无方法体、字段或逻辑改动。
- 各子包类数与设计文档逐包核对一致；测试文件迁移后总数不减（新增 `DrainBurstCapTest` 5 例）。

新增回归覆盖：

- 每帧写入上限按物理行生效：长正文与 diff 展开两种放大路径都先看到红（实际 5000 行 / 4500 行）再转绿。
- 多帧之间一行不丢、首尾顺序正确。
- 同步修掉 `render_diff_smoke` 的假红：`pump` 等待窗口此前按旧 tickRate 写死，降频后剩两帧走不完被算成失败，现改为按帧数 × 当前帧长计算。
