# v1.26.3 — 多图拖拽只显示部分图（两段根因修复）

在 [v1.26.2](v1.26.2.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-10-14。

## 修复：一批拖多张图只显示部分（两段独立根因）

用户实报「一次拖 5 张图只显示 2 张」「拖一批只显示两张」，复跑张数还会变。取证发现是**两段独立根因串联**：终端字节先被解析层丢一段（读溢出），活下来的路径再被识别层丢一段（空格切碎）。

### 根因一：批量粘贴读溢出丢弃背靠背括号粘贴

**取证（od 抓包）**：Terminal.app 多文件拖拽时，每个文件发一条**独立的括号粘贴、背靠背连发**（`ESC[200~p1 ESC[201~ESC[200~p2 ESC[201~…`）。而 `EventParser` 的批量快路径按 8KB 块整读原始流，`PasteBodyScanner` 扫到第一条终止符就收手——**同一块里排在终止符之后的字节（下一条粘贴的完整内容）被静默丢弃**。丢多少取决于终端写入与轮询的块边界运气，所以张数时多时少、不可复现。

**修复（溢出入库 + 回灌）**：`readPasteRawBulk` 扫到终止符后，把块内剩余的已解码字符与 UTF-8 残尾字节**原样入库**（`stashOvershoot`）；`readEvent` 检测到存量时以 `BacklogBackend` 包住真实 backend，按「先暂存、后流」回灌给解析器，后续粘贴各自产出独立事件。残尾解不动时替换消费，绝不卡死后续读取；输入单线程，静态暂存无需加锁。溢出粘贴正文自然走逐字符慢路径——体量只是几条文件路径，吞吐无忧；既有静默预算/跨块 UTF-8 契约全部保持。

### 根因二：未转义空格路径重组

**现象**：一批拖入的路径可能**空格原样未转义**：带空格的文件名（中文截图默认命名「屏幕快照 2026-10-14.png」一类）被空白切成碎片，每个碎片都不是文件 → **整张图静默丢失**，附件行只数得出恰好没带空格的那几张。

**修复（路径重组，歧义取最短）**：`ImageAttachmentDetector` 新增路径重组——未解析的路径样词（以 `/` `~/` 开头或含 `/`）向后按单空格拼接相邻非路径样词，拼出真实图片文件即视为一张；遇下一个路径样词 / 上限（16 词）/ 拼不出即放弃，原词保留。歧义取最短匹配（`a.png` 与 `b.png` 各自存在就按两张算），纯文字词永不参与拼接。输入框占位符化门槛由裸词改为重组单元（两处同口径），登记拼回后的完整路径——拖几张就附几张，占位符 `[IMAGE1..N]` 与附件行计数一致。

### 用户可见的变化

- 终端里一批拖入多张图：全部识别并附带，输入框 `[IMAGE1..N]` 占位符、附件行「已附带 N 张图片」与实际拖入张数一致；不再随块边界与文件名运气丢图。
- 文件名带空格（未转义形态）的图片不再整张静默丢失。
- 纯文本粘贴行为不变；逐字符慢路径本就无溢出问题，行为不变。

### 附带：文档勘误

`docs/guide/vision.md` 的视觉硬上限数字勘误：每请求用户图上限 3→10（`MAX_USER_IMAGES`）、请求视觉 token 16k→32k（`MAX_REQUEST_TOKENS`）、每回合用户图兑现 36→120（`MAX_USER_TURN_DELIVERIES`）——文档停留在放宽前的旧口径，与代码和 `AttachmentLineTest` 断言不一致。
