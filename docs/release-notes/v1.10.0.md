# springai-agentdemo v1.10.0

在 [v1.9.1](v1.9.1.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版主题是 **模型思考设置**：`/model` 列表里按 `→` 即可为每个模型独立配置思考模式与强度（各家 provider 原生参数直通），另有行内差分渲染与 IME 损坏修复、会话预压缩三项配套改进。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.10.0-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.10.0-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.10.0`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.9.1 的变化。

---

## 新功能：模型思考设置

之前思考行为完全由各模型官方默认决定，无法调整。本版起：

- 在 `/model` 列表将高亮移到某个模型后按 `→`，进入该模型的思考设置；
- 三种模式：**默认**（不干预，走官方默认）/ **开启** / **关闭**；
- 强度按 provider 原生能力直通：
  - **DeepSeek**（`deepseek-v4-pro`）：`reasoning_effort` 取 `low` / `high` / `max`；
  - **Anthropic**：effort 取 `low` / `medium` / `high` / `max`；
  - **OpenAI**：effort 取 `low` / `medium` / `high`；
  - **通义千问**：非 `qwen3-coder-next` 模型支持 token 预算（正整数），该模型仅支持开关；
  - **智谱**：`glm-5.2` 支持 effort `high` / `max`，其余模型仅支持开关。
- 设置**按模型独立记忆**，保存在 `.codetui/thinking.json`，重启后保留；
- 当前模型的思考强度显示在空闲状态栏与模型切换确认里；
- 生效范围是**主 agent 与子 agent 的模型调用**；会话摘要与网页抽取等辅助调用刻意沿用官方默认，不受影响；
- DeepSeek 的思考配置以请求体 `thinking.type`（`enabled`/`disabled`）与 `reasoning_effort` 字段送达官方 API（阻塞与流式两条链路均已实测验证）。

## 修复：终端行内渲染与 IME 损坏

接入 TamboUI 行内兼容模块并对差分渲染做了一轮系统修复：

- 行内普通帧改为宽字符安全的**最小差分提交**，动态高度帧保留重叠区域，不再整帧重刷；
- 缩放窗口合并为停稳后**只重放一次**，滚动缓冲不再堆残骸；
- CJK 输入法预编辑异步清理不再擦坏相邻行右缘，行尾单格重申升级为光标带整行重申；
- `println` 批处理后 live 区不再被挤出、启动不再下移。

## 新功能：会话预压缩

- 持久化会话历史在加载进出站请求**之前**先按预算压缩，避免超窗请求被打回；
- token 触发条件与上下文显示共用同一套记账（工具响应与工具调用参数均计入）；
- 模型上下文窗口按「显式配置 → 内置元数据 → 保守兜底」三级解析。

## 修复：ChatClient 合并链静默丢弃思考配置与工具

思考包装类此前只实现裸 `ChatOptions`，其 Builder 在 ChatClient 的 `mutate() → combineWith() → build()` 合并链里既不匹配默认 Builder 也不匹配 DeepSeek 原生 Builder，导致**模型与思考配置被静默丢掉、工具被整体跳过**。本版改为实现 `ToolCallingChatOptions` 并实现同型合并，新增端到端回归测试钉住该行为。
