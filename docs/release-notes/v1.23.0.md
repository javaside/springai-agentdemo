# v1.23.0 — `/goal` 目标循环：独立评估器 + 四族熔断 + 两级 Esc

在 [v1.22.0](v1.22.0.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-09-29。

本版一件事：**`/goal` 目标循环**——AI 编码助手常见「干一轮就停」，大任务要用户反复手动
「继续」。`/goal <完成条件>` 设定目标后，agent 跨多个 turn 自主循环：每轮结束由**独立小模型
评估器**判定条件是否达成——未满足则把结论与累积进度注入下一轮继续；满足/不可能满足则停止；
配**四族熔断**（停滞/回合错误/评估器异常/协议失败）与两级 Esc 安全阀。轮数与 token 预算
**默认无上限**（对齐 Claude Code `/goal` 与 OpenAI Codex `/goal` 的「不设默认闸门」口径），
需要兜底时 `CODETUI_GOAL_MAX_TURNS` / `CODETUI_GOAL_TOKEN_BUDGET` 显式设置。

## 功能：`/goal` 自主循环

### 问题

设定「把 AuthService 迁到新版 API，`mvn -pl server test` 退出码 0」这类可验收目标，
旧版的行为是：模型干完一轮（或撞上自己的回合预算）就停，用户必须人肉敲「继续」并复述
上下文——目标感、进度账本、完成判定全部由用户脑内维护。

### 行为

- **`/goal <条件>`**：设定目标并立即发起首轮；忙碌时照 `/continue` 先例排队。条件上限
  4000 字符（与 Claude Code/Codex 一致），空/超长拒绝且状态零变更。当前权限档为 DEFAULT
  时提示建议切 ACCEPT_EDITS/BYPASS（行为不变，仅提示——Manual 档循环会停下等批准）。
- **评估器循环**：每轮（自动轮与用户插话轮）结束后，**独立小模型**（`CODETUI_GOAL_
  EVALUATOR_MODEL=provider:model`，未配置回退 aux 轻量链）只依据滚动记录判定
  `SATISFIED / UNSATISFIED / IMPOSSIBLE`，输出四行标记协议（VERDICT/REASON/PROGRESS/
  STATE），**不能跑工具、不进对话上下文、不受压缩影响**。UNSATISFIED 时结论与 STATE
  累积账本注入下一轮 prompt（脚手架语言跟随条件，CJK 条件→中文模板）；SATISFIED/
  IMPOSSIBLE 进终态并保留报告面板。
- **用户始终在场**：评估在飞中用户插话 → 旧判定作废重评（插话改变上下文）；自动轮与
  评估之间有 3 秒可视倒计时（`CODETUI_GOAL_TURN_GAP_SECONDS=0` 关闭），Esc 一级暂停、
  二级终止；暂停态发任意消息即恢复并清零全部熔断计数。
- **四族熔断**（均为暂停语义，发消息可恢复）：**STALLED**——连续 3 轮无进展（评估器判
  stalled **或**本轮零工具调用的机器信号，后者不靠 agent 自报）；**ERROR**——回合错误
  自动续跑 2 次后暂停（Esc 取消与瞬态空流豁免）；**EVALUATOR**——评估器调用异常/超时
  连续 2 次；**PROTOCOL**——评估输出解析失败连续 3 次。多熔断同真时原因唯一
  （STALLED > ERROR > EVALUATOR > PROTOCOL）。
- **轮数与预算默认无上限**：`MAX_TURNS` 默认 0=∞（显式设值钳 1–200）、`TOKEN_BUDGET`
  默认 0=关；两者只在自动轮派发决策点清算（**软超限**：在飞轮放行到轮末），预算对激活
  基线增量计账。无上限时状态栏、面板、自动轮前缀统一显示 `N/∞`。停止边界=评估器判定 +
  四族熔断 + 两级 Esc——无人值守长任务建议显式设兜底闸门。
- **可观测**：`/goal` 面板（条件/相位/N/∞/token/streak/最近 8 条评估轨迹/运行时长）；
  状态栏 leading 指示（`◎ goal 3/∞` / 评估中 / 倒计时 / 已暂停）；评估结论带合成标记
  落库为会话事件（中段插入、CAS 写回），`-c` 恢复时渲一行审计痕迹而不重放。

### 实现中的三个关键正确性决策

- **评估结论落库改中段插入 + CAS 写回**：尾部追加会被回合 fold（`foldTrailingUserIntoOutbound`）
  折进出站文本销毁轨迹；且评估线程与 UI 线程的读-改-写天然交错，盲写会把窗口内他人写入
  覆盖（会话+磁盘同丢）。现插在最后一条 assistant 事件之前（fold 永远够不到），写回带版本
  守卫、竞态重试 ≤3 次、耗尽放弃（标记丢失良性，**绝不覆盖他人写入**）。
- **评估超时从任务开始执行起算**：单线程评估 executor 被上一个已超时仍阻塞的 HTTP 调用
  占住时，排队评估的超时在未执行就耗尽——假 PAUSED(EVALUATOR)。看门狗改为任务开跑时才
  武装，排队等待不计入。
- **epoch 代际防陈旧**：替换/重设 goal 换代递增，旧代在途评估与迟到回调按 epoch 丢弃；
  终态单调（一切迟到事件 no-op），`dispatchSerial` 单槽使「评估在飞期间用户插话」的旧
  判定过期重评。

## 验证

- `mvn -pl springai-code-tui -am clean test`：inline-patch **88** 项、code-tui **2293**
  项测试无失败、无错误（跳过 14 项为门控冒烟）。goal 专项：状态机转移表穷举（终态单调/
  暂停恢复/二次 Esc）、解析器表驱动（缺字段/双标记/大小写/围栏包裹/自注入/UTF-16 截断）、
  熔断优先级与口径（用户轮不烧配额、续跑轮烧）、stalled 重置矩阵、预算做差与软超限、
  14 个集成场景（UNSAT×2→SAT 闭环、慢评估中插话/Esc/替换条件、僵尸防护、压缩中途存活
  等并发族）、评估器无工具/无会话记忆守卫。
- **PTY 实机冒烟**（`goal_smoke.py`，真 pty 全链路 + 真模型凭据）：UNSAT→SAT 闭环、
  评估器路由到独立模型、评估标记落库存活网（重启 `-c` 恢复审计痕迹）。
