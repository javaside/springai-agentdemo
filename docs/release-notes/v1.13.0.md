# springai-agentdemo v1.13.0

在 [v1.12.0](v1.12.0.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版主题是 **缓存命中率可见**：`/context` 报告新增「缓存命中率」行（命中 / 计费输入 token 原值），状态栏常驻「缓存命中 N%」——上下文缓存是长会话最大的省钱杠杆，此前这笔账完全不可见。为此打通了整条采集链：DeepSeek 流式补 `include_usage` 请求、usage 在流终止前原子提交、缓存 token 经 nativeUsage 兜底解析。另修复一个「数据明明到账却看不见」的显示 bug：状态行超宽时动态数据被终端截断。还有一项默认关闭的新配置：`CODETUI_CO_AUTHOR` 让 code-tui 提交时在 git 提交信息末尾追加 `Co-Authored-By` 尾注。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.13.0-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.13.0-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.13.0`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.12.0 的变化。

## 新功能：缓存命中率可见（`/context` + 状态栏）

长会话里 prompt 缓存命中能省下大头输入费用，但此前 nowhere 可见。本版把这笔账摆到两处：

- **`/context` 报告**新增一行：`缓存命中率：78%（命中 120,832 / 计费输入 155,184 token）`——口径与会话累计 token 一致，命中率 = cached_tokens / prompt_tokens（DeepSeek 的 prompt_tokens 含缓存命中）。无计费输入时不打印该行。
- **状态栏** IDLE 行常驻 `· 缓存命中 78%`，紧跟 `· 上下文 N%` 之后，每秒刷新。

采集链三层（均为隐藏行为，供排查参考）：

1. **请求侧**：DeepSeek 流式默认不回 usage，请求体自动补 `stream_options.include_usage=true`；
2. **提交侧**：`UsageRecordingChatModel` 装饰器包住每家 provider 的 chatModel（主 agent / 子 agent / 摘要路径全覆盖），流式只在终止/取消时提交一次，杜绝按 chunk 重复计数；提交时机在终止信号传播给下游**之前**——否则恰在此刻读统计会缺最后一笔；
3. **解析侧**：Spring AI 2.0.0 的 DeepSeek 适配器 `DefaultUsage` 构造不填缓存字段，故从 `nativeUsage` 里的 `prompt_tokens_details.cached_tokens` 兜底读出（真实 API 实测验证）。

统计是会话级的：`/clear` 清零，压缩不清零（压缩后缓存语义变化，命中率仍反映本会话累计命中）。

## 修复：状态栏超宽时动态数据被截断

缓存命中率上线后实机一直不显示。排查证明数据链完全正常（快照 `hit%=78` 每秒到账），根因是**显示层**：满配 IDLE 状态行约 98 列（键位提示 56 + 模型名 15 + 动态后缀 27），80 列终端上尾部整段被截——「缓存命中 78%」恰在最尾，永远不可见。

本版 IDLE 行按终端宽度装填：**模型名与动态数据（上下文 / 缓存命中 / 后台任务）必须完整**，放不下时按「静态提示先让位」次序丢弃键位段（Esc 取消 → /model 切换模型 → Ctrl+C 退出 → Enter 发送）；120 列宽裕时提示全保留。回归测试 `CacheHitStatusBarWidthTest` 钉住 80 列与 120 列两种行为。

## 新功能：GitHub 提交署名（`CODETUI_CO_AUTHOR`，默认关闭）

配置 `CODETUI_CO_AUTHOR`（如 `CODETUI_CO_AUTHOR=Claude <noreply@anthropic.com>`）后，code-tui 用 git commit 提交时在提交信息末尾追加 `Co-Authored-By: …` 尾注，GitHub 会把它计为共同作者。未配置则不注入任何署名指引，行为与之前完全一致。

顺带一项启动脚本改进：`config.env` 的加载从 shell `source` 改为逐行 `read` 解析——值里的 `<` `>` 空格不再需要引号，也杜绝了 config.env 注入任意 shell 命令的可能；兼容 CRLF 行尾。
