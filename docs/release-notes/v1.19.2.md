# springai-agentdemo v1.19.2

在 [v1.19.1](v1.19.1.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版一件事：**根治「模型输出时打字卡死」**。此前在模型大量输出期间打字/插话，按键会排队数秒到完全无响应；根因（pty 实验证实）是 macOS pty 内核写缓冲仅 ~1-2 KiB，终端读端停摆（中文 IME 合成期主线程忙、终端渲染积压）时阻塞 `write(2)` 无限期挂起，而旧实现里这笔写发生在渲染线程——渲染线程睡死在 write 上，`eventQueue` 里的按键全部排队。

**下载物为两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.19.2-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.19.2-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.19.2`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.19.1 的变化。

## 修复：输出时打字卡死（三层改造）

### 库层 `AsyncPtyWriter`：pty 写剥离到守护线程

- 渲染线程的 `submit` 只入队，实际 `write(2)`/flush 由专职 `pty-writer` 守护线程执行——pty 读端停摆（IME 合成 / 终端渲染积压，实测吞吐可跌到 ~20 KiB/s 甚至无限期阻塞）时，渲染线程不再跟着睡死，按键照常处理。
- **两级字节预算**：软预算 1 MiB（大批量输出撞线即拒，调用方降级）+ 硬预算 2 MiB（小帧——打字回显、live 区差分、OSC/BEL——豁免软预算，打字不能因为正在输出大块内容被拒）。
- **字节在 `writeRaw` 返回后才释放**：写线程卡在 write 上时预算保持占用，背压对「慢设备」真实生效。
- **队空豁免保前进性**：大于软预算的合并批在队空时必须放行（否则恢复后死锁），且按软预算**分片**入队——单个超批不再整体占一个队列位，小帧可插进分片缝隙，回显延迟分布平滑。
- **分片边界避开 UTF-16 代理对**：切开则两片各自经 PrintWriter 编码 UTF-8 时孤立代理变 `?`——emoji/扩展区 CJK 内容永久损坏（红绿验证钉住）。
- **设备死亡检测**：JLine `writeRaw` 走 PrintWriter、吞掉 IOException 只置 `checkError` 标志——错误探针每次排空后主动探测，终端 tab 被关 / ssh 断线时提示用户并有界退出，不再对着不存在的屏幕静默流失内容。

### 显示层 `InlineDisplay`：延迟批与清屏屏障

- 被拒批进 FIFO 延迟队列（保序合并、绝不同步直写、绝不丢），写线程排空后武装唤醒驱动重投。
- **清屏屏障**：/clear 与 resize 重放前先排空在飞队列——否则清屏字节可跑到更早提交的旧内容批之前，「清屏了旧内容又复活」且 `ESC[3J` 无法重发。
- 关停恢复序列（光标重现/raw 模式复位）在一次性守护线程里有界直写——SIGTERM 的 shutdown hook 不再可能挂在 PrintWriter 锁上（进程杀不死问题）。

### 应用层 `CodeTuiView`：背压闸与降级提示

- writer 饱和时暂停产出新输出批（pending/流式行留在 state），防止内存无界；continuation 30ms 退避防空转。
- **/clear 屏障降级时补独立说明行**：清屏失败（反射失败或积压排不空）时除「─── 新会话 ───」分隔行外，另起一行说明「终端输出积压未排空：上方若浮现旧内容，属上一会话残留」。
- 终端注意提示（tab 标题 OSC / 响铃 BEL）改经 pty writer 队列提交——不再与模型输出抢同一把 PrintWriter 锁（直写会在 writer 持锁卡死时冻住渲染线程）。

## 测试与验收

### 新增测试

- patch 模块 **70/70**（+3）：AsyncPtyWriter 分片契约（保序/片长/不切代理对，往返编码桩可观测孤立代理损坏）、字符级总量不丢字、`JLineBackend.writer` 结构钉（探针反射链在库升级改名时红灯，而非静默降级）。
- code-tui 模块 **1832/1832**（+1）：/clear 降级提示必须两条独立 INFO（合并成一行会红）。
- 全部改动按 TDD 进行（红→绿验证），既有测试未删减或放宽断言。

### 新增冒烟：读端停摆（`stalled_terminal_smoke.py`）

真 pty + pyte 回放 + 本地 SSE 桩，复现卡死根因场景：输出高峰（2000 行）期间停读 3 秒（内核缓冲写满、pty-writer 卡在 write(2)），期间打字 13 键。三道判据：

1. **顺序**：完整回显首次可见的字节偏移 > 末行输出偏移（异步 FIFO 保证；同步写世界方向相反）——带证红开关（翻转断言方向必非零退出）；
2. **完整性**：恢复后 2000 行一行不少；
3. **静止**：排空后 2s 零终端字节。

实机验证：新 jar 上 `SMOKE PASS`（echo 437136 > last 404835）、证红开关 exit=1 红在证红断言；人工实机「输出高峰 + 打字」确认流畅无卡顿。
