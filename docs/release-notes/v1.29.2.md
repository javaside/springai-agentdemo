# v1.29.2 — 后台任务面板行尾残影修复（⏱ 任务行行尾的横线）

在 [v1.29.1](v1.29.1.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-11-01。

## 修复：⏱ 面板任务行行尾多一根横线

**症状**：后台任务面板出现后，每个任务的短行行尾多出一根横线——那是旧输入框边框
`─…╮` 的残影，任务行还会被撕裂。用户实报后用 `background_smoke.py` 场景 2 实机复现。
值得记录的教训：该冒烟脚本自 v1.19 起未再重跑、又不进 CI，v1.26.4 之后其实早已
FAIL，却没有被任何人看见——渲染层改动的冒烟欠账在第 11 个版本上兑现成了用户可见缺陷。

**根因**（pyte 逐条序列重放定位）：`InlineDisplay` 批末 live 恢复
（`appendLiveRestore`）此前选择**不逐行 EL**，赌「整块覆写能盖住残影」。这个赌注只在
live 区形状不变、restore 落点恰好是同一批旧行时成立；一旦面板出现/消失使 live 区高度
变化，restore 写到的每一行落点就成了旧 live 的**另一行**——短行（面板行）覆写满宽行
（输入框边框）时只覆盖新内容那么宽，旧行尾残留在任务行后面。println 序列本身的相对
位置自洽，没有错位，纯粹是「不擦行尾」假设失效。

**修复**：`appendLiveRestore` 改为**逐行 EL**（与首帧 full redraw 同语义），一行改动。
EL 与行内容在同一次写入里紧贴发出（`\r` + EL + 内容），不支持同步输出的终端也看不到
「边框先没后有」的行级中间帧——这正是当年选择不擦的理由，现在以紧贴写入化解。

## 测试

- 新增 **MiniVt**：测试用迷你 VT 状态机，把字节序列重放成屏幕画面再断言，补上本模块
  「纯字节断言测不出最终画面」的缺口。
- 新增 `InlineDisplayOffBottomTest`：复现实机时序（println×3 + live 逐行增长 + 耗时
  跳变 + 末条 println），断言正文完整、live 八行连续、面板短行行尾无 `─`/`╮` 残影。
- `InlineDisplayDiffTest`：EL 计数契约 1→4（正文 1 + live 3 行）。
- `background_smoke.py`：加任务行残影专项断言；「状态栏须在 rows-1」断言在 v1.26.4
  首帧不钉底后已过时（空 pty 启动 live 不贴屏底），改为按内容找状态行。
- 变异验证：把 `eraseRowTails` 改回 `false`，上述两个测试齐红，还原后变绿——证明守卫
  真的在测画面而不是空转。
- 全量：patch 模块 126 例全绿；code-tui 全量单测绿；`background_smoke.py` 五场景
  SMOKE PASS（修复前 FAIL）。

## 用户可见的变化

- ⏱ 后台任务面板的任务行行尾不再残留旧输入框边框的横线，任务行不再撕裂。
- 无新增启动参数、无新增命令、无新增配置文件、无新增环境变量；live 区形状不变的
