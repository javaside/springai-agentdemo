# springai-agentdemo v1.17.2

在 [v1.17.1](v1.17.1.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版主题：**终结「输出中打字」引发的界面卡死与终端崩溃**。模型长输出期间在输入框打字，界面可能周期性卡顿、甚至整个终端意外退出——本版从三个方向降低 ANSI 输出频率、移走渲染线程上的重活，并根治超大残行每帧处理的性能黑洞。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.17.2-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.17.2-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.17.2`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.17.1 的变化。

## 修复：输出中打字不再卡死 / 终端崩溃

### 症状

- 模型**长输出期间**在输入框打字，界面周期性卡顿（输入无响应、画面定格数秒），严重时**整个终端意外退出**（macOS Terminal.app 崩溃报告：`EXC_BAD_ACCESS`，崩溃线程在 `NSTextInputContext` / `IMKInputSession`——输入法合成被高频 ANSI 刷新打断）。
- 会话历史很大的情况下（实测 1MB+ 的会话），即使不输出，状态栏刷新也会周期性冻结界面。

### 根因（三个叠加）

1. **渲染线程上的 token 估算**：状态栏上下文用量每 ~1s 全量重算（遍历全部消息 + jtokkit 分词估算）。大会话下单次耗时数百 ms，且跑在**渲染线程**上——期间输入、重绘、按键全部冻结。实测会话历史 1.3MB 时每 ~1s 卡一次约 300ms。
2. **无限增长的流式残行**：模型输出长时间不换行时，`streaming` 缓冲无限累积（实测出现**百万字符单行**）。渲染线程**每帧**都对整段残行做预览 + 语法高亮 + 折行——O(百万) 的每帧字符串操作，把渲染线程拖死。用户一打字（事件排队）就表现为卡死。
3. **高频全量重绘**：默认 tick 40ms（≈25fps 全屏重绘）+ scrollback 下沉 33ms。内容每帧在变时（流式输出中）diff 挡不住，叠加到 Terminal.app 上冲击输入法合成 → 终端崩溃。

### 修复方式

1. **token 估算移出渲染线程**（`CodeTuiView`）：状态栏上下文用量改在独立 daemon 线程（`context-usage-refresh`）刷新，渲染线程只读 volatile 快照——大会话不再周期性冻结界面。
2. **流式残行上限 20 万字符**（`ConversationState`）：超过上限把多余部分切行下沉定稿（一次性），残行预览永远只面对 ≤20 万字符；配套回归测试 `streamingTail_capsOversizedPartialLine_bySinkingExcess`。
3. **渲染降频**（`CodeTuiView`）：tick 40ms → **100ms**（10fps），scrollback 下沉 33ms → **66ms**——输出中的 ANSI 频率大降，冲击输入法合成的概率随之大降。
4. **残行预览节流**（`CodeTuiView`）：流式残行预览只允许每 ~150ms 更新一次，不再每帧重写预览行。

### 说明

- 本版无法根治 **Terminal.app 自身的输入法崩溃 bug**（`NSTextInputContext` 空指针，崩溃栈中无 code-tui 帧）。降低 ANSI 输出频率能显著降低触发概率；若仍频繁崩溃，建议换用输入法处理更稳的 iTerm2。
- 运行中**替换发布 jar** 会导致 JVM 类加载索引与磁盘不一致，出现「类明明在 jar 里却 ClassNotFoundException」的假象（如 `OptionSpec`）。升级请**先退出旧进程，再替换文件，最后启动**。

- **回归测试** `streamingTail_capsOversizedPartialLine_bySinkingExcess`：灌入 30 万字符残行，断言残行回到上限内、超限完整行已定稿下沉、token 数量守恒。

## 升级说明

**无破坏性变更**。`config.env` 可直接沿用。无需新增环境变量。唯一行为变化是渲染频率与预览更新频率（见上），动画节奏略慢于 v1.17.1，换取流畅的输入响应与更低的终端崩溃概率。
