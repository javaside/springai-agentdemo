# v1.25.2 — 任务清单不再「建了就不更新」

在 [v1.25.1](v1.25.1.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-10-08。

## 问题

长期会话里反复出现一种失败形态：模型建好了 `TodoWrite` 任务清单，此后**整场会话再也不更新**，任务面板冻结在第一项「进行中」，而它实际已经把活干完了。真机取证（201 事件的 SDD 会话）：模型为 7 个任务追加了 8 次台账、产出 8 个提交、任务全部完成，面板却从头到尾停在 `Task 1: in_progress`。

跨语料复核（本机 15 个会话目录、322 个会话、184 个建过清单）确定了成因结构：

- **一个确定缺陷**：清单对模型是**单向**的——面板在 UI 层模型看不见，`TodoWrite` 的返回是一次性文案，环境也没有任何机制把过期清单送回上下文。于是**任何一次漏更新都不可逆**：它不产生任何可观察后果，也没有任何东西会把状态纠正回来。
- **一个统计性触发器**：「把一个工作单元记为完成」的时刻，模型手里那个"记账槽位"会被更具体的东西占掉——流程文本给的台账行（有格式模板）、委派（完成发生在子 agent 里）、长流程文本。实测控制器做出完成标记时顺手更新清单的比例：非 SDD 会话 63%、SDD 会话 37%。**冻结到底不是 SDD 专属**：冻结跨度 ≥50 且有完成标记的会话有 23 个，其中非 SDD 20 个。

同时证伪了一个曾经的候选解释：「进入执行循环前是否已有 TodoWrite 使用节奏」按同口径二分后为 0.28 vs 0.41、组内跨满量程，不构成区分变量。

## 新增

**① 过期清单提醒（两条触发路径，都只给模型看，不污染 scrollback）**

- **事件对齐**：`Task`/`ParallelTasks` 返回、`git commit`、或写入台账/进度记录之后，**下一个跳过更新的调用**当场点名。完成事件当刻刻意不提醒——那一刻清单必然还没机会更新，当场响等于每次委派都刷一遍。每回合至多响一次。
- **阈值计数**：连续 `every` 次（`CODETUI_TODO_REMIND_EVERY`，默认 8，0 = 关闭）控制器级工具调用未更新且清单仍有未完成项时提醒，负责事件路径覆盖不到的长推进。
- **提醒自带可照抄的入参**：`TodoWrite` 是整表替换（每项都要 content/activeForm/status），而竞争动作（写一行台账）成本极低——只喊「请更新」等于把重建整份清单的重活丢回模型。提醒因此直接给出整份清单 JSON，模型只需照抄改 status。快照过大（>3000 字符）时退化为紧凑列表，避免每 N 次调用注入巨型文本。

**② 系统提示词任务清单纪律段**：把更新动作**绑定到具体事件**（每完成一个任务、每次提交、每写完一条台账或进度记录之后先更新），并声明「委派的子 agent 返回并通过审查 = 一个任务完成」。此前工具描述里只有笼统的「完成后标 completed」，那正是被更具体的流程动作挤掉的一方。

**③ 任务面板过期标记**：清单久未更新时面板显式显示 `⚠ 已 N 次工具调用未更新，清单可能已过期`。此前面板冻住**用户看不出这是旧状态**，也就无从催办——而语料显示用户催办确实能把会话拉回正轨（出问题的那场恰好全程无人催办）。这是把用户接回反馈回路的最小改动。

## 修复

1. **`git commit` 的识别口径**：入参是 Bash 的 `arguments` JSON（`{"command":"…"}`），命令行开头的 `git` 前面跟的是**引号**，而正则按 shell 语义锚定「行首或命令分隔符」——于是 `git commit -m x` 这种最自然的写法**永远不匹配**，只有 `cd X && git commit` 恰好被 `&&` 救了一命。失败形态是"只是提醒不响"，没有报错、没有异常。改用词边界，并允许 `git -C <dir> commit`、`git -c k=v commit`、`git --no-pager commit` 这类夹全局选项的写法。同一 bug 也存在于取证脚本里，全语料有 30 次提交因此被漏计。
2. **台账写入纳入完成事件**：事件对齐路径最初只认委派返回与提交，而 SDD 场景的完成标记几乎全是台账写入（`cat >> progress.md` / python 内联写回）——该路径在 SDD 上因此基本不响应，且与取证脚本口径不一致（它一直把台账计为完成标记），我们自己的纪律段也明写「每写完一条台账后先更新清单」。判定要求「台账路径 + 写入语义」同现，故 `cat progress.md`（读回台账）不算。
3. **验收指标的两处「静默归零」**：取证脚本判定注入时，① 原本要求「返回文本以收尾句结尾」，而本版把可照抄的 JSON 挪到文案末尾后该判据永不匹配；② 注入文本存在 TOOL 事件里而 `toolCalls` 在 ASSISTANT 事件里，原按「同一事件取 `toolResponses`」判定则永远取空。两处都只是安静地报 0，看起来完全像「功能没生效」。现改为「行首标记」+「按 `toolCallId` 跨事件配对」，并做双向校验（已知正例 >0、已知负例 =0）。另修：传入目录里没有 SDD 会话时，空分组会让脚本抛 `StatisticsError` 打断整份报告。

## 验证

- **零件与装配层**：`TodoStaleReminderTest` 15 例（事件武装/不残留/每回合至多一次/提交与台账识别/照抄契约/退化形态）、`ToolEventCallbackTest` 9 例、`AgentToolsTodoDisciplineTest` 2 例、`ConversationStateTest` 新增 5 例（面板标记阈值、更新即消失、全完成不报、子 agent 不计、`/clear` 复位）、`AgentToolsSystemPromptTest` 1 例、`AgentToolsTodoReminderEndToEndTest` 1 例（真实 `AgentTools.build` 产物上走「建清单 → 提交 → Read」，断言提醒落在结果尾部且其 JSON 能被真实 `TodoWrite` 接受）。
- **两个由用例抓出的真实缺陷**：装配级全链路用例当场抓到上面第 1 条（`git commit` 永不匹配）；`AgentToolsSystemPromptTest` 由变异验证补上——删掉 `.param(TODO_DISCIPLINE_KEY, …)` 后它会变红并报出 `Not all variables were replaced …`，而此前该变异全绿（「构建 runtime」不等于「渲染提示词」，漏配 param 只有第一个真实请求才会炸）。
- **真机**：`TodoReminderLiveSpikeTest` 三次真实回合，模型均自建并自行维护清单；其中一次「提交后跳过更新 → 提醒当场注入 → 模型随即更新」闭环。
- **真机受控实验**（复刻台账工作流，实验组 vs 对照组 `CODETUI_TODO_REMIND_EVERY=0`）：实验组两轮各注入 3 次、**均在 3 个调用内被采纳（响应率 1.00）**，对照组注入 0。边界如实标注——对照组同样把清单维护住了，故本实验**证明不了**「没提醒会冻住」，只证明「一旦跳过，提醒会响且被采纳」。
- **真实工作会话里的现场注入**：功能装到本机后，当天修这个问题的会话（359 次工具调用）出现 3 次注入，**全部被采纳**；其中一次采纳发生在第 4 个调用，故按「3 次调用内」的口径响应率记为 0.50（口径未事后放宽）。
- `mvn -pl springai-code-tui -am test`：**2334 例、0 失败、无错误、跳过 16 项**（`@EnabledIfEnvironmentVariable` 门控的真机用例）。
- `mvn -pl springai-code-tui javadoc:javadoc`：通过，无 Javadoc 错误或警告。
