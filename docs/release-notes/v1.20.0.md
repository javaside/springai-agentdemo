# springai-agentdemo v1.20.0

在 [v1.19.2](v1.19.2.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版四件事：**① 主 agent 流式路径的两层自动重试 + 界面 ↻ 重试提示**——此前主 agent 的流式调用对故障零重试，流一断回合直接「⚠ 出错」，用户只能整回合重发，上下文越深损失越大；本版把「网关抖一下 → 整回合报废」变成「网关抖一下 → 界面提示重试 → 自动恢复」，并按 Claude Code 的可见性标准**每次重试都在界面上显示一条「↻ 重试」提示**。**② GPT-6 Astra 成为 OpenAI 默认模型**。**③ Markdown 表格渲染**——模型输出的表格在终端里终于对齐了（此前按字符数补格、CJK 两位错位）。**④ 项目名常驻状态行行尾**——多开 code-tui 窗口一眼分清哪个在跑哪个项目。

子 agent 不套这套新 L1/L2 两层机制，aux（摘要/抽取）路径也不受影响；但判据共享后，子 agent 的既有重试判据同步并入流式瞬态形态——其空闲超时/空流也会重试而非立即失败（见下「关键机制点」）。

**下载物：** 两个自包含运行包 `springai-code-tui-1.20.0-dist.tar.gz`（macOS / Linux 首选）/ `springai-code-tui-1.20.0-dist.zip`（Windows 首选），解压即用、无需构建，内容与惯例一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.20.0`**。SHA-256 校验和见文末「发布前验证」。

## 功能：主 agent 流式两层重试 + ↻ 提示

故障按「是否已下发内容」分成两层，各归各治：

- **Layer 1（传输层，透明零下发重试）**：在连接错 / 429 限流 / 5xx / 首字节空闲超时 / 空流 / 解析错等**零下发**失败时，新的 `RetryingStreamChatModel` 在 ChatModel 层自动重发（指数退避 0.5s×2ⁿ 封顶 4s、显式关 jitter），用户无感。判据与退避从子 agent 的重试提取成唯一真相源 `RetryPolicy` 共享，两套机制不再漂移。
- **Layer 2（回合级续跑）**：**mid-stream 断流**（已下发过内容后失败，例如长回合里网关抖一下）无法在传输层透明重试（重发会与已消费的 chunk 拼接成重复内容），改由 `CodingAgent` 回合级续跑——UI 把半截残行落定保留，显示 ↻ 提示行，退避（1s×2ⁿ 封顶 4s）后**在 defer 内重建 spec、重走完整 advisor 管线**（同一 turnId、同一 Disposable 管辖，Esc 随时可取消、绝不复活）。

两条路径都经新事件 `onRetryScheduled`（5 参：turnId / attempt / maxAttempts / backoffMs / reason）驱动 UI：

- 提示行 `↻ 重试中 (2/5·传输)：{reason}，0.5s 后重发` / `↻ 重试中 (1/2·续跑)：{reason}，1.0s 后重发`（reason 经根因推导 + 单行化截断，80 列内不折行）；
- 状态栏新增 `↻ 重试中`（波光动画，80 列宽度预算内与 `Esc 取消` 完整可见；退避剩余时长仅在 ≥100 列宽终端附加），首个新 chunk 到达自动回到思考/输出态；
- 半截输出按滚动 TUI 的诚实约束**保留在屏幕上**（append-only，无法撤回已 println 的整行），↻ 行后接新流输出。

## 关键机制点

- **开关 `CODETUI_STREAM_RETRY`**：自动重试是用户透明的花钱行为，必须有闸——`all`（默认）| `l1` | `l2` | `off`，四档在装配层与 CodingAgent 层一致生效（`l1Enabled ? 包 RetryingStreamChatModel : 直通`，无多余 API）。**⚠ `l2` 档当前真实链 ≈ off**：SII（L2 续跑的触发类型）唯一生产源是 L1 的 classify，`l2` 档 L1 不包装则主链无 SII、L2 filter 永不命中——档位按 API 前瞻保留，真正生效待「只 classify、不重试」的 L1 变体。
- **共享判据反哺子 agent（行为增强，非回归）**：判据/退避提取成 `RetryPolicy` 唯一真相源后，子 agent 的 `RetryingChatModel` 按同一判据判瞬态——空闲超时（`StreamIdleTimeoutException`）与空流也入子 agent 的瞬态判据，**空闲超时会退避重试而非立即失败**；主 agent 新加的 RetryStream 装饰层仍只包主链，子 agent 与 aux（摘要/抽取）结构上都不被误包（守卫测试钉死）。
- **续跑形状分流**：断点会话尾部裁回合法前缀后按形状处理——纯文本段断（形状①）把「问题 + 待送达插话 + 系统通知」合并成**一条** user 重放；工具循环中途断（形状②）不重放问题（历史已有），系统通知走插话通道单独注入。两形状分别用单锁原子 API `takeAllForResumeUser()` / `refillForResume()` 处理插话队列，杜绝「两条连续 user → 400」与 Esc 竞态下的 notice 跨回合泄漏。
- **安全前提（实测/字节码核验）**：`SessionMemoryAdvisor` 只在本回合 user 上无条件 append、续跑产生的空文本 user 在三处清除点（prepareResume / 成功收尾 / 终态失败）全域清掉；advisor 链破坏性消费 → 续跑**必须在 defer 内重建 spec**（同一 Flux 二订阅会抛 `IllegalStateException`）；退避等待期 Esc 立即 dispose，defer 体有 disposed 复查，绝不发幽灵请求。
- **失败文案诚实**：重试耗尽才在终态错误上拼「已自动重试（传输 a 次/续跑 b 次）仍失败：{根因}」；零重试错误（401/400）原样透传不加前缀；取消（Esc）静默、不出「回合已取消」报错。
- **收费如实记账**：空流尝试/续跑各轮的 usage 都是网关真实计费，各记一笔不回滚（缓存命中率分子分母同增不失真）。
- 判据、退避、事件载荷均有测试钉死：`RetryPolicyTest` / `RetryingStreamChatModelTest`（虚拟时间退避序列 0.5/1/2/4、SII 类型穿透、emitted 口径、空流记两笔）/ `CodingAgentTurnResumeTest`（19 用例：形状分流、Esc 窗口 latch 桩、执行序对抗夹具、载荷序列、①→① 连断 notice 不叠加、L1-only 耗尽「传输 4 次/续跑 0 次」文案、blank 清除）/ UI 宽度测试 / 装配守卫（主链链序、aux/子 agent 不被误包）。

## 功能：GPT-6 Astra 接入（OpenAI 新默认）

- `gpt-6-astra`（2026-09-03 发布）入 OpenAI 内置清单并**成为默认模型**；effort 五档 `low/medium/high/xhigh/max`，官方档位无 `none` → 不支持关闭（`gpt-5.6` 保持三档可关闭，无行为漂移）。
- 内置上下文窗口 `openai:gpt-6-astra` → 1,050,000（官方模型页核实）；视觉前缀精确到 `gpt-6-astra`——家族其他成员未经核实不进视觉名单，astra 系 dated 快照/fast id 同为 Astra 模型、前缀放行。
- `vision.md` 前缀表、内置清单说明与 `config.env.example` 示例同步。
- ⚠️ 模型分阶段开放中：key 无 early access 会报模型不可用，`/model` 切回 `gpt-5.6` 家族即可。

## 功能：Markdown 表格渲染（终端里终于对齐了）

此前渲染器**没有表格分支**，表格行原样打印——模型按字符数补齐格子、终端按显示宽度排版（CJK 占 2 列），用户实报「表格显示就乱了」。本版补上表格块渲染：

- **轻量表样式**：表头加粗 + 一条 `─` 分隔线 + 空格对齐（GFM 对齐符 `:---` / `---:` / `:---:` 生效），不画竖线、行尾不补白；宽度一律按**显示宽度**计（`CharWidth`，与折行口径同源）。
- **超宽不丢字**：先削列宽、再格内折行，削到头退回原样输出，对任意输入（含 null/残缺表格）不抛异常。
- **块缓冲与边界**：scrollback 只能追加、印出去改不了，列宽必须在打印前算完——表格块先缓冲、块结束才输出；块结束判定由状态机管理（含围栏守卫、降级态、缓冲上限，Esc 取消排空不留半截表）。
- 测试：单元（`MarkdownTableTest` / `MarkdownRendererTableTest`）+ 视图级 flush 触发点（`CodeTuiViewTableFlushTest`，变异脚本验证盲区）+ 真 pty 冒烟；设计见 `docs/superpowers/specs/2026-09-04-code-tui-markdown-table-design.md`（三轮评审）。

## 功能：项目名常驻状态行行尾（多开窗口可辨）

多开 code-tui 时分不清哪个窗口在跑哪个项目。本版口径（经一次方案迭代收敛）：

- **项目名常驻状态行行尾**：空闲/思考/重试/跑工具/收尾提示五种常态行都以 ` · <目录名>`（启动目录最后一段）收尾，80 列窄终端下不挤掉「Enter 发送 / Esc 取消」——项目名一律拼在最后、不进任何宽度预算，空间不够时终端先截它；目录名超 24 显示宽截 23 列加 `…`。
- **tab 标题退回纯提醒**：`⏳ … 等待输入` / `✓ … 已完成` 瞬间标题 + BEL，平态恢复纯品牌串 `Code TUI`。（曾试过项目名进 tab 标题，实测被终端截短否决——多数终端只显示十几个字符，项目名与提醒文案互相挤压。）
- 模态/面板接管状态行时不显示（临时覆盖层，收起自然回来）。
- 测试：`CodeTuiViewProjectNameStatusTest`（离屏渲染断言屏幕真含项目名——纯拼接测试证不了「出现在屏幕上」）；既有宽度测试（`BusyCacheHitStatusTest` / `CacheHitStatusBarWidthTest`）钉死键位提示不被挤压。

## 内部质量：故障注入日志断言式接管（ExpectedLog）

`springai-tamboui-inline-patch` 测试基建：预期 SEVERE/WARNING 不再泼进构建输出，也不许裸静音——新增 `testutil/ExpectedLog`（capture 接管被测 logger → awaitRecord 带超时轮询命中并显式断言级别/消息/thrown → close 兜底绊线：捕获到 WARNING+ 却未断言的记录直接判测试失败）。`AsyncPtyWriterTest` 设备死亡族与 `InlineTuiRunnerEventDrivenTest` 事件循环吞异常用例迁移到它，「确实打了这条日志」本身成为被测契约。
