# v1.30.0 — 自定义子 agent（六层目录发现 + 热重载）+ /agents 命令（分组单行式）

在 [v1.29.3](v1.29.3.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-11-04。

两大主题：**自定义子 agent**——不改代码、不重启进程，把 `<名>.md` 放进六层约定目录即可扩展
`Task` / `ParallelTasks` 的合法 `subagent_type`；**`/agents` 命令**——把这份装配清单（内置 +
自定义、含来源层标签）呈现给人看，并经两轮排版迭代（分组单行式、窄窗口渐进降级）收敛到
恒一行不折行。

## 一、自定义子 agent —— 六层目录发现 + Task/ParallelTasks 热重载

**用法**：在以下六层目录任一层放置 `<名>.md`（frontmatter + 正文，frontmatter 的
`name` / `description` 必填，`tools` / `disallowedTools` / `model` 可选——`skills`
解析但不生效，按 spec 明确记为非目标）：

```
~/.claude/agents → ~/.agents/agents → ~/.codetui/agents
<项目>/.claude/agents → <项目>/.agents/agents → <项目>/.codetui/agents
```

层序与 `SkillCatalog` 完全同源（skills.sh / agents.md 生态按检测到的 agent 定向落目录：
Claude Code 落 `.claude`，Cursor/Codex 等落 `.agents`）——技能侧已认的六层，子 agent 侧
同口径采纳，空目录静默跳过，多扫无害。

- **合并与覆盖**：与内置 4 个子 agent 合并，同名后层覆盖（项目 > 用户 > 内置）；文件按
  文件名排序装载，目录迭代序的不确定性被消除（同层同名覆盖可复现、roster 行序跨
  reload 不漂移）。
- **立即可用**：自定义 agent 进入 `Task` / `ParallelTasks` 工具描述的 roster，成为合法
  `subagent_type`，主 agent 下一次请求即可选择委派。
- **热重载**：`/reload` 同时重扫子 agent 目录（与技能同一命令、同一种代理模式），摘要
  新增一行「子 agent：内置 4 + 自定义 N」；roster 下一次请求即更新。
- **容错**：单个 `.md` 坏（IO 失败 / 缺 `name` / 缺 `description`）只跳过该文件并记
  warning，不影响其余文件与内置 4 个。

**实现要点**（为什么必须走代理）：`AgentTools.build` 的 subagentSpecs 原是 build 期一次性
快照，烘焙进 `Task` / `ParallelTasks` 的工具描述 roster 与路由 map——运行期新增定义不能
原地改 map。同构方案来自 `ReloadableSkillTool`：实例恒定的 `ToolCallback` 代理 +
`volatile Snapshot` 原子替换（Spring AI `DefaultToolCallingManager` 每次请求都现调
`getToolDefinition()`，代理转发后下一次请求模型即见新 roster）。新类三个：
`SubagentCatalog`（六层发现 + 合并覆盖 + 坏文件容错，与内置段同一次迭代双写 specs 与
infos 投影）、`ReloadableSubagentTool`（Task/ParallelTasks 的热重载代理，装饰链
Permission→ToolEvent 包在代理外层只包一次，delegate 重建不穿透装饰层）、
`SubagentReloader`（**单次装载喂双代理**，防两个代理各自快照之间的漂移窗口）。装配由
`CodeTuiApplication` 生产构造点显式接线（漏传不编译错——null 合法——已在提交内堵死）。

**安全边界**（装配级测试钉死）：子 agent 工具集来自 `decoratedList` 过滤，而
`Task` / `ParallelTasks` / `TaskOutput` / `ListTasks` / 记忆工具 / `ExitPlanMode` 都不在
其中——自定义 agent 即便 `tools` 里写了这三个，也一个都拿不到，**递归 fan-out 在构造上
不可能**，无需新增防护代码。

一个踩坑记录：装载 URI 必须用 `Path.toUri()`——手拼 `"file:" + path` 对含 `#` / `?`
的文件名必坏（URL fragment/query 截断）。

## 二、/agents 命令 —— 列出全部子 agent（含来源层标签）

`/agents`（插在 `/skills` 与 `/reload` 之间，语义相邻、无前缀冲突）只读无闸门，输出
内置 + 自定义全部子 agent。数据面新投影 `AgentInfo`（name/description/source，后扩
allowTools/denyTools/model）——不让 `SubagentSpec`（systemPrompt 大正文）泄进 UI 层，
与技能侧 `SkillInfo` 同套路；「内置」标签为 agent 侧独有。来源层标签与 `SkillCatalog`
逐字同口径（用户·claude / 用户·agents / 用户 / 项目·claude / 项目·agents / 项目），
同名覆盖时换条目但位置保持、标签跟随胜者。

## 三、/agents 排版两轮迭代 —— 分组单行式 + 窄窗口渐进降级

**重排为分组单行式**：初版两行式（名字 + 缩进描述全文折行）在描述长时版面散乱——改头行
计数 + 内置/自定义分组，每条恒一行「名字（按显示宽度对齐）+ 工具范围 + 指定模型 + 描述
首句（>60 字符截 57 + …）」。工具空口径 = 全工具；`model` 空 = 跟随当前模型；`deny`
剔除集中做脚注，来源层标签只在自定义组逐条显示（纯内置会话里逐条标「内置」是噪音）。

**窄窗口渐进降级**：行宽此前没对着终端宽度算——scrollback 出口 `TextWrap` 会把超宽行
软折行且续行顶格，窄窗口下列对齐被打穿、每条裂成多行。`agentRow` 改纯函数按序构造六级
候选、取第一个放得下的：完整行 → 砍描述首句 → 砍 model → 工具清单截前 2 个 + … → 只剩
name + 标签（仍按 nameWidth 对齐）→ 极窄放弃对齐、name 截 `width-5` 列 + …（不切半宽
字符）。降级次序按信息价值从低到高丢：**desc 是身份提示最先丢，name 是委派锚点永远最后
丢**；宽度下限钳 20。内置组尾随填充剥除（不可见却虚增显示宽，会把放得下的行挤进下一级）。

  覆盖跟随、tools/model 投影）用例；`SubagentReloaderTest` / `AgentRuntimeTest` 联动
  （装配后 Task roster 含项目层自定义 agent；`reloadSkills` 触发子 agent 重载 + 摘要

  `tools=[Task,MemoryCreate,ExitPlanMode]` 一个都拿不到，正向对照 `[Read]` 可得（自建
  runner 恒绿是假绿灯，故钉在装配级）。
- 新增 `CodeTuiViewAgentRowTest` 11 例（六级降级纯函数直测，先红后绿）；
  `CodeTuiViewSlashMenuTest` 命令总数 21→22 机械平移（/agents 入表）。

## 用户可见的变化

- **新增 `/agents` 命令**：分组单行式列出全部子 agent（工具范围/指定模型/描述首句），
  自定义条目带来源层标签；窄窗口下逐级降级、恒一行不折行。
- **自定义子 agent**：六层约定目录放 `<名>.md` 即生效，同名项目层 > 用户层 > 内置；
  `/reload` 重扫并输出「子 agent：内置 4 + 自定义 N」。
- 敲 `/` 的补全菜单多一条命令（21 → 22 条），窗口公式本身未动。
- 无新增启动参数、无新增配置项、无新增环境变量、无新增网络权限。
