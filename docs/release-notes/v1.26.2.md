# v1.26.2 — 抖音 ZWNJ 粘贴输入框错位修复

在 [v1.26.1](v1.26.1.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-10-12。

## 修复：粘贴含隐形格式字符的文案后输入框错乱、行尾重复

**现象**：向输入框粘贴抖音复制的文案（如《We Never (Remix) (若如初见)》…氛围感BGM。）后，输入框显示错乱，行尾「最后一句」重复。抖音文案里散布着多个 **U+200C（ZWNJ，零宽不连字）** 之类的隐形格式字符——它们是复制行为带进来的，肉眼不可见。

**根因（DSR 光标探针实测）**：tamboui 0.4.0 的 `CharWidth` 把这类 Cf 格式字符判为 0 列，而 Terminal.app 的 TTBuffer 记账**每个记 1 列**（raw 模式 `CSI 6n` 逐字符实测：ZWNJ/zwsp/词连接符/U+FEFF/软连字符均 1 列；组合附标与 VS16 实测 0 列）。事故原文 7 个 ZWNJ：模型算 98 列、终端实际画 105 列——差分渲染的游标逐列落后，重绘时新内容写偏，表现为错乱与行尾重复。与 v1.26.0 的 VS16 宽度事故同构、方向相反，是宽度口径事故链的第五轮。

**修复（宽度表单点同源）**：把 `CharWidth` 纳入 `springai-tamboui-inline-patch` shadow（同 Buffer/InlineDisplay 机制，运行期优先加载）：

- Cf 格式字符（U+200B–200F、U+2060–2064、U+FEFF、U+00AD）零宽改 **1 列**，各自独立成格；组合附标（Mn）与 VS16 维持 0 列（实测复验）。上游 widgets（`TextInput` 输入框本体、`Paragraph`、`TextElement`）直接引用 `CharWidth`，shadow 一处修正、布格/游标/折行/输入框光标全部同源。
- **ZWJ 去粘合**：实测 Terminal.app 对 `👨‍👩`（ZWJ 家族序列）按 2+1+2 记 **5 列**、不做字形合并记账，原「粘合为单 glyph 2 列」的口径是虚构。`TerminalWidth` 的粘合分支、`Buffer` 的 `appendToLast` 拼格、`CharWidth.substringByWidth` 的 ZWJ 原子性机制三处同删——最后一处按码点身份触发，保留会漏记宽度、截出超预算内容。

**用户可见的变化**：

- 粘贴含 ZWNJ 等隐形字符的文案：布局不再错乱；每个隐形字符占一个空列（终端字体对该列的字形回退，裸 `cat` 同样如此）。**内容一字不动**，发送/存储的原文不受影响。
- 家族 emoji（`👨‍👩`）：按码点占 5 列（独立 emoji + 连接符空列），与 Terminal.app 原生记账一致；其他终端若做字形合并，会显示为带空隙的独立 emoji——本产品宽度口径以 Terminal.app 实测为准（既有决策惯例）。

**遗留（已记录，非本次范围）**：U+2028–202F（定向格式）与 U+2066–206F（定向隔离）未实测，暂维持 0 列；旗帜对 2 列口径未做 DSR 核对。证据链与完整实测表见 [2026-10-11-zwnj-format-width-design.md](../superpowers/specs/2026-10-11-zwnj-format-width-design.md)。

## 验证

- TDD 全程：新增 `CharWidthShadowTest`（表值/去粘合/截取一致性）与 `TerminalWidthTest`/`BufferGraphemeCellTest` 事故用例先看到 13 红（含揪出事故原文实为 7 个 ZWNJ、合计 105 列的数数错误），实现后全绿；旧「家族单 glyph 2 列」断言按实测口径更新。
- `mvn -pl springai-code-tui -am clean test`：**2378 例、0 失败**（跳过 18 项为环境变量门控的真机用例）；`mvn -pl springai-code-tui javadoc:javadoc` 无错误无警告。
- 用户真机活体复测：粘贴事故原文，输入框不再错乱、行尾不重复。
