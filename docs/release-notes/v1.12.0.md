# springai-agentdemo v1.12.0

在 [v1.11.1](v1.11.1.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版主题是 **OpenCode Go provider 的思考档位按模型实测并扩充模型清单**：把此前一刀切的 `reasoning_effort` 三档，改为按每个模型返回其真实支持的档位（DeepSeek / GLM / Kimi / MiniMax / 混元旗舰可用到 `max`），同时模型清单从 15 项扩到 22 项、剔除上游已不可用的坏模型。另有一处 CI 修复：构建与打包命令补 `-am`，避免 CI 去 Maven Central 解析不进远程仓库的兄弟模块而失败。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.12.0-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.12.0-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.12.0`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.11.1 的变化。

---

## 新功能：OpenCode Go 思考档位按模型实测

v1.11.0 引入 OpenCode Go provider 时，`reasoning_effort` 统一只暴露 `low / medium / high` 三档——因为当时实测只确认了 `mimo` 上游只认这三档，为求全上游通用而一刀切保守。这带来一个副作用：网关下的 `deepseek-v4-pro` 等旗舰模型用不上其真实支持的 `xhigh` / `max` 档，思考强度选择器里选项偏少。

本版把思考能力从「按 provider 一刀切」改为「**按 modelId 返回各自真实支持的档位**」（`EFFORT_CAPS`），并用真实 key 逐个模型实测（2026-08-15）：

| 档位集合 | 模型 |
| --- | --- |
| `low / medium / high / xhigh / max` | `deepseek-v4-pro`、`deepseek-v4-flash`、`glm-5.2`、`glm-5.1`、`glm-5`、`kimi-k3`、`kimi-k2.6`、`kimi-k2.5`、`minimax-m3`、`minimax-m2.7`、`hy3` |
| `low / medium / high / xhigh`（无 `max`） | `qwen3.8-max`、`qwen3.7-max`、`qwen3.7-plus`、`qwen3.6-plus`、`qwen3.5-plus` |
| `low / high / max`（不可关闭思考） | `glm-5.3` |
| `low / medium / high`（保守三档） | `mimo-v2.5-pro`、`mimo-v2.5`、`gpt-5.6-luna` |

- 未收录的模型（含经 `OPENCODE_GO_MODELS` 自定义的）回退到保守的 `low / medium / high` 三档；
- `gpt-5.6-luna` 实测时被 Cloudflare 限流（403），档位尚未测得，暂按保守三档回退、待补测；
- 关闭思考仍映射为 `none`，仅 `supportsDisable=true` 的模型可关（`glm-5.3`、`kimi-k2.7-code`、`minimax-m2.5`、`mimo-v2.5` 不可关）。

## 新功能：OpenCode Go 模型清单 15 → 22

依据网关 `/models` 的实测可用性重排清单：

- **补入 10 项**：`glm-5.3`、`glm-5`、`kimi-k2.6`、`kimi-k2.5`、`qwen3.7-max`、`qwen3.6-plus`、`qwen3.5-plus`、`minimax-m2.7`、`minimax-m2.5`、`mimo-v2.5`；
- **剔除 3 项上游不可用**：`mimo-v2-omni`（Unsupported model）、`hy3-preview`（Model is unavailable）、`grok-4.5`（Endpoint is unavailable，503）——避免用户选中即报错，上游恢复后再加回；
- **修正过时注释**：`qwen3.7-max` 此前被认为只能走 Anthropic 原生 `/messages`，实测已可经 `/chat/completions` 使用，故本版补回清单。

首项 `deepseek-v4-pro` 仍为默认模型；`OPENCODE_GO_MODELS` 自定义（首项为默认）的语义不变。

## 修复：CI 构建与打包命令补 `-am`

`springai-code-tui` 依赖同仓库、但不发布到 Maven Central 的兄弟模块 `springai-tamboui-inline-patch`。CI 工作流（`.github/workflows/ci.yml`）的「测试」与「打发布包」两处命令此前只带 `-pl` 不带 `-am`，Maven 转而到 Maven Central 解析该模块而失败。本版给两处命令补上 `-am`，就地构建兄弟模块；`-am test` 与 `-am package -Pdist` 均已本地验证通过。
