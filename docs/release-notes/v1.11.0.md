# springai-agentdemo v1.11.0

在 [v1.10.0](v1.10.0.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版主题是 **新增 OpenCode Go provider**：一个聚合网关，一把 key 即可接通 MiniMax / Kimi / GLM / DeepSeek / 通义 / MiMo / 混元 / OpenAI / xAI 等多家模型，复用 OpenAI 兼容通路接入，并支持 `reasoning_effort` 三档思考强度。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.11.0-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.11.0-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.11.0`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.10.0 的变化。

## 新功能：OpenCode Go provider

在 DeepSeek / 智谱 GLM / 通义千问 / Anthropic / OpenAI 之外，新增 **OpenCode Go**（OpenCode Zen 的 Go 订阅）聚合网关 provider：

- 一把 `OPENCODE_GO_API_KEY` 即可接入 MiniMax / Kimi / GLM / DeepSeek / 通义 / MiMo / 混元 / OpenAI / xAI 等多家模型；
- 其 `/chat/completions` 与 `/models` 是 OpenAI 兼容端点（Bearer 认证），因此复用现有 `OpenAiChatModel` 通路接入，与智谱 provider 同理，**未引入新的第三方依赖**；
- 默认 `baseUrl` 为 `https://opencode.ai/zen/go/v1`，可经 `OPENCODE_GO_BASE_URL` 覆盖（海外网关或自建代理）；
- 内置模型清单 15 项，首项 `deepseek-v4-pro` 为默认模型，可经 `OPENCODE_GO_MODELS` 自定义（首项仍为默认）。

**思考强度走 `reasoning_effort`**，接入 v1.10.0 的模型思考设置：

- 网关统一校验并翻译 OpenAI 兼容的 `reasoning_effort`（合法全集为 `none / minimal / low / medium / high / xhigh / max`）；
- 实测（2026-08-14，真实 key）各家上游并非全盘接受完整档位——`mimo` 上游只认 `low / medium / high`（`minimal` / `xhigh` 被 400 拒），故只暴露**全上游通用的 `low / medium / high` 三档**；
- 关闭思考映射为 `none`（各家实测均能关掉），默认不干预仍不带 `reasoning_effort`。

**两处刻意保守**：

- `qwen3.7-max` 仅暴露在 Anthropic 原生 `/messages` 端点上，走 OpenAI 兼容的 `/chat/completions` 会被拒（`not supported for format oa-compat`），因此默认清单**不含** `qwen3.7-max`；需要通义旗舰时可用 `qwen3.8-max`。等上游暴露按模型路由的元数据后再考虑接入 `/messages` 分支。
- 图片输入仍未验证网关是否透传，视觉能力沿用默认 `TEXT_ONLY`（未知即不支持）；要用视觉请直接走对应原生 provider。

## 文档与配置示例

- 根 `README.md`、`springai-code-tui/README.md` 的多 provider 清单与「对话模型」说明同步加入 OpenCode Go；
- `bin/config.env.example` 新增 `OPENCODE_GO_API_KEY` / `OPENCODE_GO_BASE_URL` / `OPENCODE_GO_MODELS` 三项示例与说明；
- 启动时「未检测到 key」的提示文案补入 `OPENCODE_GO_API_KEY`。

## 修复：同名模型串号

OpenCode Go 聚合网关与各家原生 provider 会提供**同名模型**（如 `deepseek-v4-pro`）。此前 `/model` 选择、思考设置到 `.codetui/model.json` 记忆整条链路都只用裸 `modelId` 定位，provider 靠「列表序靠前」猜，导致配置 A 家的同名模型时 B 家也一起被改。

本版把模型身份从裸 `modelId` 升级为 `(providerId, modelId)` 二元组并贯穿全链路：

- `/model` 列表、思考设置、`.codetui/model.json` 记忆都精确按 provider + 模型定位；
- 跨 provider 重名的模型在列表条目尾部标注来源（如 `deepseek-v4-pro · opencode-go`），其余条目保持原样；
- `.codetui/model.json` 改记 `providerId + modelId`，并向后兼容旧 `lastModel` 单键（迁移为 provider 未知、回退靠前 provider）。
