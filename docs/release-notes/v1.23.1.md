## 修复：Terminal.app 崩溃诱因根治——scrollback 打印改纯滚动（零 `ESC[1L` 插行）

**症状**：模型持续输出期间打字（尤其中文拼音），界面完全冻结、必须杀终端；有时 Terminal 直接崩溃退出。该症状历史修复多轮（v1.17.1 渲染线程异常防护、v1.18.3 帧限速、v1.19.2 pty 异步写、v1.21.0 drain 预算）后仍复发。

**取证定案（不是猜测，是证据链）**：

1. **崩溃报告**：`~/Library/Logs/DiagnosticReports/` 两份 `Terminal-*.ips` 与用户两次卡死时刻精确吻合，均为 Terminal 主线程内存管理崩溃——一份崩在 SwiftUI `DisplayList.append` → malloc `EXC_BREAKPOINT`，一份崩在 `NSTextInputContext` 处理输入法（TSM）事件时空指针（`EXC_BAD_ACCESS`）。即：**Apple Terminal.app (2.15/470.2, macOS 26.5.2) 自身的 bug**，code-tui 是触发者与受害者。
2. **冻结现场堆转储**：卡死期间对 code-tui 进程 `jcmd GC.heap_dump`——渲染循环/pty 写线程/输入线程全部健康空闲，队列空、零积压、监听器接线完好。code-tui 内部无死锁。
3. **负载画像**：冻结会话事件流 22 分钟仅 ~300KB、峰值 2 事件/秒——排除「输出洪峰压垮」。
4. **对照**：Claude Code（Ink 渲染）同终端同输入法不崩——差异在输出字节模式。

**真机二分（四轮定案）**：给渲染层加临时开关逐行为关闭——`--force-fullredraw`（全量重画替代差分片段）**仍崩**；`--band-off`（禁用 IME 光标带重申）**仍崩**；`--scroll-append`（scrollback 改纯滚动、零 `ESC[1L` 插行，Claude Code 语义）**不崩且零新增崩溃报告**；默认模式实机复现配方确认不崩。

**根因**：code-tui scrollback 打印路径的 `ESC[1L` 中部插行 + 每批 live 区整块重申，高频触发 Terminal 自身的内存管理缺陷（SwiftUI 渲染缓存 / 输入法事件处理两条崩溃路径均被复现）。

**修复内容**：

- `InlineDisplay.println` 默认改**纯滚动模式**（Claude Code 语义）：首帧 `ESC[999B` 把 live 区钉到屏幕底部（CUD 被终端钳制在末行，空屏启动也成立），此后每条正文走「底行 CRLF 滚屏腾行 → 上移清残影写正文 → live 区整块重画回底部」，全程零插行。
- 保留 `--insert-lines` 启动参数（或 `CODETUI_INSERT_LINES=1`）回退旧插行行为，供对照与逃生；开启时开场第一屏明示一行。
- 二分用的另外三个临时诊断开关（`--force-fullredraw` / `--band-off` / `--preview-off`）实验完成后已随实验矩阵一并移除，不进发布物。

**验证**：

- inline-patch 89 用例 + code-tui 全套 2294 用例无失败（含旧插行协议契约改为显式 `INSERT_LINES` 模式钉住、新增纯滚动等价契约用例）；
- 无头 VT100 仿真验证（`dev/terminal-stress/scroll-verify.py`）：空屏启动钉底成立、消息按序上滚、帧贴底、零残影、零 `ESC[1L`；
- 真机两轮（开关模式 + 默认模式）在原必崩配方下不崩，`DiagnosticReports` 零新增。

**已知边界**：Terminal.app 自身的 bug 并未消失——本版拔掉的是我们这边的高频触发器（引信）。建议长期换 iTerm2 / ghostty / WezTerm；若在其他使用模式下仍见 Terminal 崩溃，可先以 `--insert-lines` 对照排除，再看崩溃报告签名是否同族。
