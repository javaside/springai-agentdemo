# springai-agentdemo v1.18.2

在 [v1.18.1](v1.18.1.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版为 OpenCode Go 接入官方视觉实验模型，并把视觉能力从“只看裸 modelId”收紧为 **provider + model 联合判定**，避免聚合网关中的同名模型错误继承原生 Provider 的图片能力；同时阻止消息处理期间切换模型，避免排队图片或插话在实际请求时静默降级为纯文本。

**下载物为两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.18.2-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.18.2-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.18.2`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.18.1 的变化。

---

## OpenCode Go 支持官方视觉实验模型

OpenCode Go 的内置模型清单新增：

- `deepseek-v4-flash-vision-exp`（视觉实验 · 图片理解）

默认模型仍为 `deepseek-v4-pro`，现有配置与模型选择顺序不变。图片继续通过 OpenAI 兼容的 `image_url` 请求通路发送。

OpenCode Go 的视觉能力采用严格白名单：目前只允许 `deepseek-v4-flash-vision-exp` 接收图片。即使 `OPENCODE_GO_MODELS` 配置了 `gpt-5.*`、`claude-*` 或其他在原生 Provider 下支持图片的同名模型，也不会自动开放视觉，避免未经网关确认的模型收到图片后返回 400。

---

## 修复：视觉能力按 Provider 隔离

此前 UI 附件闸门和请求前图片兑现主要依赖全局模型名前缀。如果聚合网关与原生 Provider 存在同名模型，例如都叫 `gpt-5.6-luna`，全局名单无法表达“OpenAI 原生端点支持，但 OpenCode Go 未声明支持”的差异。

现在两层统一使用当前 Provider 的能力判定：

- UI 提交附件前，通过当前 provider + model 判断是否放行；
- 请求真正交给 ChatModel 前，通过该 ChatClient 所属 provider + Prompt model 判断是否兑现图片；
- OpenAI、Anthropic、通义、智谱和 DeepSeek 原生 Provider 继续沿用原有视觉名单，不受影响；
- 未显式声明视觉能力的新 Provider 安全回退为纯文本；
- `CODETUI_VISION=off` 全局关闭开关保持有效。

这项调整只改变能力归属，不改变图片预算、会话存储、引用结构和原生 Provider 的发送通路。

---

## 修复：有待处理消息时不再切换模型

带图消息可能被排队到下一回合，插话则进入正在执行的旧回合。如果在消息真正送达前切换模型，UI 放行时看到的模型和实际请求模型可能不同：图片不会误发，但可能只剩引用文本，用户却不知道模型没有看到图片。

现在 `/model` 选择器在以下任一条件成立时拒绝确认切换，并保留选择器：

- 当前回合或压缩仍在进行；
- 仍有在飞子 agent；
- 普通消息队列非空；
- 仍有待送达插话。

待消息全部处理完成后即可正常切换。这样在飞回合、插话和排队消息始终使用一致的模型身份与视觉能力。

## 文档与维护性

- 新增实现索引和图片处理实现原理文档，按“会话消息 → 当轮请求副本 → Provider 请求体”的完整链路说明图片如何只临时进入请求、不长期占用上下文。
- 补齐公共 API Javadoc 参数说明并启用 doclint 检查，修正文档注释语法问题。
- 澄清 `LlmProvider.capabilities` 的安全默认值：默认纯文本，支持视觉的 Provider 必须显式声明。

## 质量

发布前验证：

- `mvn -pl springai-code-tui -am clean package -Pdist` → **Tests run: 1660, Failures: 0, Errors: 0, Skipped: 10**（10 个 skipped 为环境变量门控的联网/真机探针），并成功生成两个发布包。
- 视觉能力、附件闸门与模型切换定向回归 → **Tests run: 48, Failures: 0, Errors: 0, Skipped: 0**。

新增回归覆盖：

- OpenCode Go 只有官方视觉模型支持图片；同名全局视觉模型不会串用能力。
- Provider 判定为纯文本时，UI 不放行附件，请求层也不兑现图片。
- 原生 Provider 的既有视觉模型继续支持图片。
- 回合进行中或存在排队消息时，模型切换被拒绝且不会落盘。

## 升级说明

**无配置变更，无破坏性变更。** 直接替换运行包即可。

行为调整：存在运行中、排队或待送达消息时，`/model` 会提示先等待处理完成；这是为了保证消息使用的模型和图片能力不在途中变化。

升级时请先退出旧进程，再替换文件并重新启动。
