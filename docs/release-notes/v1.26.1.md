# v1.26.1 — 技能描述块标量修复 + agent-utils 升 0.13.0

在 [v1.26.0](v1.26.0.md) 基础上的**修订版**（patch）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

发布日期：2026-10-09。

## 修复：技能 description 的 YAML 块标量解析损坏

**现象**：`/skills` 清单与 `/skill` 选择器里，hyperframes 全家（本机 55 个技能中 9 个）描述显示为空（实际是一个光秃秃的 `>`），模型侧 `<available_skills>` 里还混着 `<Mandatory entry point>…` 之类的幽灵 XML 元素——模型据此无法判断何时调用这些技能，路由信号全废。

**根因（上游库缺陷）**：`spring-ai-agent-utils` 的 `MarkdownParser` 逐行按第一个冒号切 key/value，不认 YAML 块标量。技能生态常见的 `description: >` 折叠多行写法被解析成裸指示符 `">"`；带冒号的续行被当成新 key-value 塞进 frontmatter，再经 `Skill.toXml()` 把整个 map 逐条转成 XML 烘进工具描述。已向上游提 [issue #107](https://github.com/spring-ai-community/spring-ai-agent-utils/issues/107)（0.13.0 仍未修）。

**修复（双侧）**：

- 新增 `SkillFrontmatterRepair`：检测到裸指示符即重读 `SKILL.md` 补解析（`>` 族空格连行、`|` 族保留换行、支持 `-`/`+` 截断后缀），`/skills`、`/skill` 面板显示真实描述。
- `ReloadableSkillTool` 在 reload 时按修复记录重建损坏的 `<skill>` 块（健康块与库模板原样保留），模型看到的 `<available_skills>` 即为真实描述；修复在快照里算好缓存，不随每请求重复执行。
- 实现中钉住一个隐蔽坑：库的 frontmatter 是 `HashMap`，幽灵元素可能排在 `<name>` **之前**输出（hyperframes-audio 实测），块匹配不能假设元素顺序。

## 升级：spring-ai-agent-utils 0.10.0 → 0.13.0

升级前对 0.13.0 字节码逐一 javap 核查全部接触面（`Skill` record / `Skills` / `SkillsTool.Builder` / `Todos` 系列类型 / `MarkdownParser` / 各工具 builder / `AgentEnvironment`），签名兼容；Spring AI 基线不变（同 2.0.1），`spring-ai-session` 0.5.0 共存无冲突；精简覆盖的 `AUTO_MEMORY_TOOLS_SYSTEM_PROMPT.md` 上游 0.10.0→0.13.0 逐字节无变化。

- **`TodoWriteToolAdapter` 随上游修复删除**：0.13.0 [#74](https://github.com/spring-ai-community/spring-ai-agent-utils/pull/74) 把 `todoWrite(Todos)` 改为 `todoWrite(List<TodoItem>)`——修的正是当初双层 `todos` 嵌套 schema 逼出本项目适配层的同一个坑。适配层自此冗余，连同其测试整体删除（净删 123 行），装配直用库工具，行为不变。
- 0.12 的 ExecBackend/Docker 沙箱执行、目录围栏与 0.13 的 `addSkill` 编程注册均为 opt-in，本次未启用，留作后续评估（对「无沙箱已知风险」是潜在改善方向）；ShellTools 执行层重构走 LocalExecBackend，默认行为不变。

**上游变更传递到本产品的可见变化**（0.10.0 与 0.13.0 字节码常量逐一比对确认）：

- **Read 工具描述重写**（[#85](https://github.com/spring-ai-community/spring-ai-agent-utils/issues/85)/#86）：旧版 *"Assume this tool is able to read all files on the machine"* 诱导模型拿 Read 读任意文件；新版如实声明 **只读 UTF-8 文本、要求绝对路径**（"Reads a UTF-8 text file … The path must be absolute"）。模型对 Read 的调用预期随之收敛——二进制/图片不再被引导去 Read。
- **Grep/Glob/列目录的相对路径解析基准修正**（#94）：相对 `path` 参数原先按 JVM 启动目录解析（code-tui 不在项目根启动时相对路径查询会查错位置或被拒），现按工具的 `workingDirectory`（本项目即项目根）解析。
- **TodoWrite 工具描述措辞**（#67）：`for your current coding session` → `for your current session`（去掉 coding 限定，与删除适配器后描述直随上游叠加，模型可见的指引文本有微小变化）。

## 改进：技能目录兼容 .claude / .agents 安装约定

开源技能项目的安装命令（`npx skills add` 等，skills.sh 生态）按检测到的 agent 定向落目录、不写 `.codetui`，且版本行为在漂移——只认一个目录会在「另一半机器」上漏技能。现两约定都读：

- 六层加载顺序即优先级（同名后加载者覆盖）：`~/.claude/skills` → `~/.agents/skills` → `~/.codetui/skills` → `<root>/.claude/skills` → `<root>/.agents/skills` → `<root>/.codetui/skills`。原则：**项目 > 用户，自有 > 兼容**。
- 同一技能多处安装不会重复（镜像仓库场景按 name 双重去重）；`/skills` 来源标签细化为 用户·claude / 用户·agents / 用户 / 项目·claude / 项目·agents / 项目。

## 改进：系统提示词固化「大输出分批」纪律

2026-10-09 真机事故：模型写大文档时把整篇内容塞进单个巨型 `Write` 工具调用，SSE 层的 chunk 合并器会整段缓冲参数、聚齐前下游收不到任何数据——万字文档（≈16K+ token）流式生成超过 300s 流空闲超时，被判定「零下发可透明重试」后重新生成同样巨型调用，形成恰好每 300s 一挂的死循环（安装目录日志连续 7 次超时实证，curl 探针排除大文本/长 prompt/tools 数组等其它因素）。现场验证有效的解法——先 `Write` 首块、再 `Edit` 逐批追加——已固化进系统提示词工作方式段，并新增用例钉住该纪律不被误删。

## 移除：任务面板的「清单可能已过期」用户提示

任务面板里「⚠ 已 N 次工具调用未更新，清单可能已过期」这行 UI 标记确认无用，整体移除（含计数器、样式与钉住旧行为的 5 个测试）。驱动模型更新清单的另一条通道——把过期清单怼回模型上下文的 `TodoStaleReminder`——刻意保留，不受影响。
