# springai-agentdemo v1.17.0

在 [v1.16.0](v1.16.0.md) 基础上的**功能版**（minor）。核心交付物仍是终端编码智能体 **`springai-code-tui`**。

本版唯一主题：**DeepSeek 视觉模型支持**。DeepSeek 官方 2026-08-21 上线了多模态视觉模型 `deepseek-v4-flash-vision-exp`（实验性质，纯文本能力与 V4-Flash 正式版持平，多模态 Agent 能力接近 Opus-4.8），本版让 code-tui 完整接上它——你贴的图和工具产的图都能真正送进模型，同时保持既有「图片从不进会话记忆、单回合花费有硬上限」的全部纪律。

**下载物仍是两个自包含运行包（解压即用，无需构建）：**

- `springai-code-tui-1.17.0-dist.tar.gz`（macOS / Linux 首选）
- `springai-code-tui-1.17.0-dist.zip`（Windows 首选）

两者内容一致：启动脚本（`bin/`）+ 主 jar + 全部运行期依赖（`lib/`）+ 配置示例 + 使用指南 + `LICENSE`/`NOTICE`/`README`。运行时界面版本标识为 **`v1.17.0`**。

> 完整功能全景与安全声明见 [v1.3.0 发布说明](v1.3.0.md) 与 [v1.0.0 发布说明](v1.0.0.md)；本文只列出相对 v1.16.0 的变化。

## 新功能：DeepSeek 视觉模型支持

### 模型可直接选用

`deepseek-v4-flash-vision-exp` 已加入 DeepSeek 内置模型清单（`/model` 直接可切，默认模型仍为 `deepseek-v4-pro` 不变）。视觉能力按模型 id **前缀**判定（名单见 [视觉输入指南](../../springai-code-tui/docs/guide/vision.md#哪些模型能看见)），DeepSeek 前缀 `deepseek-v4-flash-vision` 恰好唯一命中该模型、不误伤纯文本的 `deepseek-v4-flash`——即使官方后续去掉 `-exp` 后缀或改名，判定仍生效。**未知模型一律不发图**（名单外模型即使配置进 `DEEPSEEK_MODELS` 也不会把图发出去吃 400）。

图片计费：每张图按服务端自动缩放后计费，**单张最多 384 token**（价格与 V4-Flash 一致）。

### 真正的图片注入链路

本版解决了一个库层面的硬障碍：**spring-ai-deepseek 2.0.0 的消息序列化会静默丢弃图片**——它组装请求时只用消息文本，`UserMessage` 上挂的图片 `Media` 直接被丢掉（对比 spring-ai-openai 原生支持图片）。因此 DeepSeek 视觉必须走一条专属通道：

```
兑现器挂 Media（通用层，与其它 provider 共用）
  → DeepSeek 专属：把当轮图片注册进进程内注册表（按「消息序号:图片序号」）
  → 原生序列化（图片被丢，但文本结构保留）
  → HTTP 层改写器：按序号取图，把 user 消息的 content
    从 string 改写成 [text 块 + image_url/file 块]
  → DeepSeek API
```

关键性质：

- **只动 user 消息**，`system`/`assistant`/`tool` 一概不碰；**无图请求逐字节不变**（纯文本请求零行为变化）。
- **fail-open**：改写器查不到图片 key 一律原样放行——图片注入失败绝不连累请求本身。
- **图片仍只活当轮**：字节从不进会话存储，跨轮不累积上下文，聊 100 轮看过 50 张图，请求里也只有当轮那几张。
- **硬上限沿用**：每请求用户贴图 ≤3 张 + 工具产图 ≤1 张 + 6k 视觉 token；每回合累计兑现 ≤12 张·次（约 21.6k token 封顶）。用户图先过预算且保底不淘汰。

### 两种传输通道（默认内联）

| 通道 | 方式 | 何时用 |
|---|---|---|
| **base64 内联**（默认） | 图片字节 base64 编码成 `data:image/...;base64,...` 随请求体发出，**零额外往返** | 默认；本项目图已压到 ≤4 MiB，远低于 32 MiB 内联上限 |
| **Files API**（`DEEPSEEK_VISION_TRANSPORT=files`） | 先 `POST /files` 上传拿 `file_id`，请求里写 `{"type":"file","file_id":...}`，sha 幂等（同字节只上传一次）、单图上限 64 MiB | 偏好官方推荐路径 / 想省请求体时 |

两条路**计费完全相同**（都按每图最多 384 token），files 省的是带宽与请求体大小。**上传失败自动降级内联**——files 是增强不是依赖，绝不让一次上传失败把图片丢掉。

### 默认内联的取舍（本版的决策记录）

选内联做默认，是因为本项目图片已由 `ImagePreparer` 压到 ≤4 MiB / 长边 1568，内联形态零额外往返、无文件生命周期、失败面最小（字节随请求走，没有「上传成功但引用 400」的归因难题）。

**已知局限（本版未修，按需再议）**：同一回合内每次工具迭代都会重发请求（无状态请求的固有代价），内联意味着同一张图的字节被反复送；`DEEPSEEK_VISION_TRANSPORT=files` 可以在这一层省下传输量（上传一次拿 `file_id`，后续迭代只引用 id，请求体从 ~MiB 级降到几十字节——省的是带宽/延迟，不是钱）。`file_id` 目前只活在进程内、不持久化，跨轮引用同一张图仍会重新上传；理论上可把 `file_id` 写进引用块跨轮/跨会话复用，改动引用块结构与兑现链路，留待后续版本评估。

## 质量

发布前验证：

- `mvn -pl springai-code-tui test` → **Tests run: 1596, Failures: 0, Errors: 0, Skipped: 10**（10 个 skipped 全部为 env 门控的真机探针）
- `mvn -pl springai-code-tui -am clean package -Pdist` → BUILD SUCCESS

本版新增回归网：

- **`DeepSeekProviderVisionTest`**：视觉名单精确判定（`deepseek-v4-flash-vision-exp` 支持、纯文本 `deepseek-v4-flash`/`deepseek-v4-pro` 不支持）、内置清单含新模型且默认仍为 pro、`DEEPSEEK_VISION_TRANSPORT` 解析。
- **`DeepSeekVisionRegistryTest`**：图片注册表 put/take/clear/key，take 消费即删。
- **`DeepSeekVisionBodyCodecTest`**（9 例）：user 消息 content 改写为 text+image_url/file 块、文本块逐字保留、无命中逐字节不变、非 user 消息不碰、多图顺序、流式入口仍注入 `stream_options`、思考与视觉组合、畸形 JSON 抛错。既有 `DeepSeekThinkingBodyCodecTest` 5 例不改即绿（两参重载行为不变）。
- **`DeepSeekThinkingChatModelVisionTest`**（5 例）：注册先于 delegate、call/stream 后注册表清空、纯文本请求不碰注册表、Files 成功/失败降级两条分支（修复后为真断言——桩改为「检查不消费」，删掉清理逻辑测试立即红）。
- **`DeepSeekFileStoreTest`**：multipart 表单含 `file` + `purpose=user_data`、sha 幂等（同字节只上传一次）、上传失败返回 empty、`parseFileId` 变体。
- **`DeepSeekVisionSmokeTest`**：真机探针（`CODETUI_LIVE_TESTS=1` 才跑，双 env 门控），走**流式生产路径** + 颜色断言——纯红图发给 `deepseek-v4-flash-vision-exp`，实测模型答「红色」；探针若改走阻塞路径（不触发 HTTP 改写）会假阳性，本版已修正为与生产同路。

**审查过程抓到并修复的真缺陷**：测试清理断言曾是空断言（桩自己消费 key，删掉清理逻辑测试照样绿——已改桩为检查不消费并做突变验证）；探针曾走阻塞 `call()` + 默认思考配置，实际不触发视觉改写（假阳性——已改走流式生产路径 + 颜色断言，实测红色答对）；`ModelContextWindows` 窗口表已补视觉模型条目（否则 `/context` 会误显示 128K 而非真实的 1M 级窗口）。

## 升级说明

**无破坏性变更**。`config.env` 可直接沿用。

新增一个**可选**环境变量（不设即用默认）：

```bash
export DEEPSEEK_VISION_TRANSPORT=files   # DeepSeek 视觉走 Files API（默认 base64 内联）
```

配套更新：

- `springai-code-tui/README.md`：内置模型说明句加入 `deepseek-v4-flash-vision-exp`。
- [视觉输入指南](../../springai-code-tui/docs/guide/vision.md)：模型支持表 DeepSeek 行、内置清单可用性、`DEEPSEEK_VISION_TRANSPORT` 开关、384 token 计费、默认内联的取舍与已知局限、验证范围。

> **DeepSeek 视觉模型是实验性质**：官方可能随时调整行为；本工具对未知模型一律不发图（fail-safe），切换后若遇到异常可 `CODETUI_VISION=off` 整体关闭视觉链路（引用照常，零行为变化）。
