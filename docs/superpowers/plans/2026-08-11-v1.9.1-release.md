# v1.9.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `/skill` 大量技能闪动修复及下载运行文档整理发布为 springai-code-tui v1.9.1 正式版。

**Architecture:** 沿用 v1.9.0 的发布模式：六个 Maven POM 使用统一版本，独立 release notes 作为仓库和 GitHub Release 的单一正文来源，Maven `dist` profile 生成 tar.gz/zip。先完成版本与说明，再构建并校验最终归档，最后提交、tag、推送并创建正式 Release。

**Tech Stack:** Maven 3.9+、Java 17、maven-assembly-plugin、Git、GitHub CLI、Python 3 发布说明转换脚本。

## Global Constraints

- 版本号固定为 `1.9.1`，tag 固定为 `v1.9.1`。
- 核心发布物只有 `springai-code-tui` 的 tar.gz 与 zip 自包含归档。
- 不新增依赖，不改变权限、模型调用或技能注入语义。
- 运行环境仍为 JDK 17+，支持 macOS / Linux / Windows。
- 任一测试、构建、归档检查、校验或上传失败都必须停止后续发布步骤。

### Task 1: 版本与发布说明

**Files:**
- Modify: `pom.xml:20`
- Modify: `springai-core-demo/pom.xml:10`
- Modify: `springai-agent-demo/pom.xml:10`
- Modify: `springai-boot-demo/pom.xml:10`
- Modify: `springai-jline-demo/pom.xml:10`
- Modify: `springai-code-tui/pom.xml:10`
- Create: `docs/release-notes/v1.9.1.md`
- Modify: `CHANGELOG.md:9-12`

**Interfaces:**
- Consumes: v1.9.0 tag、`v1.9.0..HEAD` 提交、既有 release notes 格式。
- Produces: Maven project version `1.9.1`；可直接用于 GitHub Release 的 `docs/release-notes/v1.9.1.md`。

- [ ] **Step 1: 将六个 POM 中项目/父版本改为 1.9.1**

精确替换项目根目录及五个主模块 POM 中：

```xml
<version>1.9.0</version>
```

为：

```xml
<version>1.9.1</version>
```

不要修改 `.worktrees/` 下文件，也不要修改依赖版本。

- [ ] **Step 2: 编写 v1.9.1 发布说明**

创建 `docs/release-notes/v1.9.1.md`，正文必须包含：

```markdown
# springai-agentdemo v1.9.1

在 [v1.9.0](v1.9.0.md) 基础上的修订版（patch）。核心交付物仍是终端编码智能体 `springai-code-tui`。

本版主题是 `/skill` 大量技能选择器稳定性修复：选择器不再一次渲染全部技能，而是使用最多 10 项的跟随窗口，避免面板超过终端高度后 InlineDisplay 与终端滚动反复重排。所有技能仍可用方向键遍历并按 Enter 挂载。
```

后续章节依次写明两个 `1.9.1` 下载物、修复根因与行为、下载运行文档整理、质量、SHA-256 占位区、许可。SHA 区先使用明确标记 `构建完成后写入最终校验值`，Task 2 必须替换后才能提交。

- [ ] **Step 3: 更新 CHANGELOG 索引**

在 v1.9.0 之前加入：

```markdown
| [v1.9.1](docs/release-notes/v1.9.1.md) | 修订版 | **`/skill` 大量技能不再闪动**：技能选择器改为固定高度的跟随窗口，避免终端反复滚动重排；仍可遍历并挂载全部技能；同步理顺发布包下载运行入口与 JDK 17+ 说明 |
```

- [ ] **Step 4: 校验版本只改了目标位置**

Run:

```bash
git diff --check
grep -R '<version>1.9.0</version>' --include=pom.xml --exclude-dir=.worktrees .
grep -R '<version>1.9.1</version>' --include=pom.xml --exclude-dir=.worktrees .
```

Expected: `diff --check` 退出 0；第一条 grep 无输出；第二条恰好命中六个 POM。

### Task 2: 发布构建与归档验证

**Files:**
- Modify: `docs/release-notes/v1.9.1.md`（写入最终 SHA-256 与测试数量）
- Generated: `springai-code-tui/target/springai-code-tui-1.9.1-dist.tar.gz`
- Generated: `springai-code-tui/target/springai-code-tui-1.9.1-dist.zip`

**Interfaces:**
- Consumes: Task 1 的 Maven 版本 `1.9.1` 与 release notes 初稿。
- Produces: 两个最终、已校验的发布归档及其 SHA-256。

- [ ] **Step 1: 执行完整 dist 构建**

Run:

```bash
mvn -pl springai-code-tui clean package -Pdist
```

Expected: `BUILD SUCCESS`，测试 `Failures: 0, Errors: 0`，生成两个文件名含 `1.9.1` 的归档。

- [ ] **Step 2: 检查 tar.gz 和 zip 内容**

Run:

```bash
tar -tzf springai-code-tui/target/springai-code-tui-1.9.1-dist.tar.gz > /tmp/code-tui-1.9.1-tar.txt
unzip -l springai-code-tui/target/springai-code-tui-1.9.1-dist.zip > /tmp/code-tui-1.9.1-zip.txt
```

两份清单都必须包含：

```text
bin/code-tui
bin/code-tui.cmd
bin/config.env.example
springai-code-tui.jar
lib/
README.md
LICENSE
NOTICE
docs/guide/skills.md
```

- [ ] **Step 3: 核对 jar manifest 版本**

将 tar.gz 解压到临时目录后执行：

```bash
unzip -p <解压目录>/springai-code-tui.jar META-INF/MANIFEST.MF | grep 'Implementation-Version: 1.9.1'
```

Expected: 精确输出 `Implementation-Version: 1.9.1`。

- [ ] **Step 4: 写入最终测试统计与 SHA-256**

Run:

```bash
shasum -a 256 \
  springai-code-tui/target/springai-code-tui-1.9.1-dist.tar.gz \
  springai-code-tui/target/springai-code-tui-1.9.1-dist.zip
```

把两个完整哈希写入 release notes 的校验区，同时根据 Surefire 汇总写入实际测试总数；删除所有 `构建完成后写入最终校验值` 文本。

- [ ] **Step 5: 重新构建最终归档并固定最终 SHA**

因为 release notes 会被 assembly 打入归档，更新说明后必须再次运行：

```bash
mvn -pl springai-code-tui clean package -Pdist
shasum -a 256 springai-code-tui/target/springai-code-tui-1.9.1-dist.{tar.gz,zip}
```

若哈希与说明中的值不同，用本次最终值更新说明。发布归档不再重建；release notes 的 SHA 只用于仓库和 GitHub Release 正文，不要求归档内部副本自指一致。

- [ ] **Step 6: 最终静态检查**

Run:

```bash
git diff --check
python3 scripts/publish-release-notes.py --print v1.9.1 > /tmp/v1.9.1-release-body.md
```

Expected: 两条命令退出 0；转换后的正文无失效相对仓库链接。

### Task 3: 提交、标记与正式发布

**Files:**
- Commit: Task 1 和 Task 2 的版本、CHANGELOG、release notes 改动。
- Tag: `v1.9.1`
- GitHub Release assets: 两个 `1.9.1` 归档。

**Interfaces:**
- Consumes: Task 2 已验证的最终归档、最终 SHA 与 release body。
- Produces: origin/main 上的发布准备提交、远端 `v1.9.1` tag、正式 GitHub Release。

- [ ] **Step 1: 提交发布准备改动**

Run:

```bash
git add pom.xml */pom.xml CHANGELOG.md docs/release-notes/v1.9.1.md
git commit -m "$(cat <<'EOF'
release: v1.9.1 发布准备

修复 /skill 在大量技能下因面板高度失控导致的持续闪动，
同步更新下载运行说明、版本号、发布说明与最终归档校验值。

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>
EOF
)"
```

Expected: 一个非空发布准备提交，只包含上述八个文件。

- [ ] **Step 2: 推送 main 并确认同步**

Run:

```bash
git push origin main
git status --short --branch
```

Expected: `main...origin/main`，无 ahead/behind、无工作区改动。

- [ ] **Step 3: 创建并推送 annotated tag**

Run:

```bash
git tag -a v1.9.1 -m "springai-agentdemo v1.9.1"
git push origin v1.9.1
```

Expected: 远端新增 tag，`git rev-parse v1.9.1^{}` 等于发布准备提交 SHA。

- [ ] **Step 4: 创建正式 GitHub Release 并上传资产**

Run:

```bash
gh release create v1.9.1 \
  springai-code-tui/target/springai-code-tui-1.9.1-dist.tar.gz \
  springai-code-tui/target/springai-code-tui-1.9.1-dist.zip \
  --repo javaside/springai-agentdemo \
  --title "v1.9.1 —— /skill 大量技能不再闪动" \
  --notes-file /tmp/v1.9.1-release-body.md \
  --verify-tag
```

Expected: 返回 GitHub Release URL，且不是 draft/prerelease。

- [ ] **Step 5: 发布后核验**

Run:

```bash
gh release view v1.9.1 --repo javaside/springai-agentdemo \
  --json tagName,name,isDraft,isPrerelease,assets,url
```

Expected:
- `tagName` 为 `v1.9.1`；
- `isDraft=false`、`isPrerelease=false`；
- assets 恰有 tar.gz 和 zip，名称均为 `1.9.1`；
- 两个资产 digest 与 release notes 的 SHA-256 一致。
