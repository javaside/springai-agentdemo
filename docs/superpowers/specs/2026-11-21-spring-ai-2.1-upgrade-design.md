# Spring AI 2.0.1 → 2.1.0 升级 · 设计文档

- 日期：2026-11-21
- 分支：`feature/upgrade-spring-ai-2.1`
- 状态：已核准（基于 2026-11-21 的完整评估，用户确认执行）

## 目标

1. `spring-ai.version` 2.0.1 → 2.1.0，全模块编译、code-tui 全量测试通过。
2. 六处版本联动同步完成（见下表），运行期无 NoSuchMethodError / NoClassDefFoundError。
3. 钉行为测试与 2.1.0 新契约对齐（如 `getText()` null → `""`），且只允许「钉旧行为」的断言转红。
4. 真机冒烟通过：DeepSeek（thinking + vision + 缓存命中率 + 续跑）、Anthropic（SDK 3.x 新认证路径）。

## 非目标

- 不改写教学课程的 ChatMemory 内容（`springai-agent-demo` 的滑窗记忆课保留，仅接受
  deprecation 编译警告；3.0.0 移除前再整体换口径）。
- 不引入 2.1.0 新特性（Decision Models、FinishReasonCategory 等），只做兼容升级。
- 不动 `springai-tamboui-*`、`springai-jline-demo`（pom 无 spring-ai 依赖，实测 grep 为空）。
- 不清理 2.0.1 时代的防御性补丁（`.timeout(Duration.ZERO)`、DeepSeek SSE 层 usage 读取等），
  仅在实测证明冗余时才考虑另行删减。

## 已核准的事实依据（全部实测）

以下结论决定改动范围，逐条带来源：

1. **DeepSeek HTTP 层改写器前提不变**：2.1.1-SNAPSHOT 源码
   `models/spring-ai-deepseek/.../DeepSeekChatModel.java#createRequest`：USER/SYSTEM 消息仍
   `message.getText()` 序列化为纯 string content、**media 完全忽略**；`ToolResponseMessage`
   仍 flatMap 展开为 N 条消息；框架不自动设置 `stream_options.include_usage`（全文件 grep 为空）。
   → `DeepSeekThinkingBodyCodec` / `DeepSeekVisionMediaRegistry` 的「user 序号对齐」与
   stream_options 注入逻辑全部安全。
2. **`DeepSeekApi.Usage` 结构不变**：`promptTokensDetails().cachedTokens()` 原样保留
   → `CacheUsageExtractor` 兼容。
3. **2.0.1 的 `OpenAiChatOptions` timeout PT1M 默认回归在 2.1.0 已消除**：字段
   `private final @Nullable Duration timeout`，无默认值赋值 → `.timeout(Duration.ZERO)`
   保留无害（防御性保留，见非目标第 4 条）。
4. **流式 chunk `getText()` 永不为 null**：2.1.0 无 part 的消息保留空 text part
   （`DeepSeekChatModel` 源码注释明示此契约）→ 生产口径 `hasContent`（`!= null && !isEmpty()`）
   不受影响；`AdvisorResubscribeBehaviorTest` 中钉「usage-only chunk getText()==null」的断言
   必须重校准。
5. **官方 session 与社区 0.5.0 同包名同类名**：`org.springframework.ai.session.SessionService`
   （getEvents/appendMessage）、`DefaultSessionService`、`SessionEvent`、`compaction.*`、
   `advisor.SessionMemoryAdvisor`（`builder(sessionService)`、`SESSION_ID_CONTEXT_KEY`）在
   官方 2.1.0 源码中逐一核对存在 → code-tui 的 Java 代码预计零改动或极小改动。
6. **agent-utils 0.14.0 破坏性变更不触及本项目接触面**：项目只用
   `AskUserQuestionTool/AutoMemoryTools/FileSystemTools/GlobTool/GrepTool/ShellTools/SmartWebFetchTool/TodoWriteTool/AgentEnvironment`；
   0.14.0 的 `CrossSessionRecallTools` 包迁移与 `AutoMemoryToolsAdvisor` 顺序调整均未使用
   （grep 实测）。**但** prompt 覆盖文件（`AUTO_MEMORY_TOOLS_SYSTEM_PROMPT.md` 等）须按
   0.14.0 jar 重新 diff（历史核查清单要求）。
7. **Anthropic SDK 2.x → 3.8.0 是最大风险**：认证头 `X-Api-Key` → `Authorization: Bearer`
   （SDK 内部行为，`apiKey()` 传法不变）；client builder API
   （`AnthropicOkHttpClient.builder().apiKey().timeout()`）与 `AnthropicChatModel.builder()
   .anthropicClient(...)` 需编译验证；项目未设 temperature/topP/topK（grep 实测），不受废弃影响。
8. **`MessageAggregator` 不再拼接 partial `ToolCallPart`**：真实模型会另发完整调用，
   `RetryingChatModel` 不受影响；仅当测试 stub 只发 partial tool call 时会静默丢调用，
   需按新契约在同 index 补发完整 `ToolCallPart`。
9. **ChatMemory 系列废弃（3.0.0 移除）仅影响教学模块编译警告**：code-tui 主链路已在
   session memory 上（grep 实测 `ChatMemory` 仅出现在注释）。
10. **2.1.0 DeepSeek 续跑回放 reasoning**：带工具的请求会回放 `reasoning_content`——
    重试/续跑的请求体变化需真机冒烟确认（上下文/计费）。

## 被淘汰的备选及理由

- **只升 spring-ai、不动 Boot**：agent-utils 0.14.0 硬性要求 Boot 4.2 / Framework 7.1；
  且 0.13.0 针对 Spring AI 2.0.1 编译，2.1.0 下 parts 重构的 API 面未验证，留 0.13.0 风险
  更大。淘汰。
- **继续用社区版 spring-ai-session 0.5.0**：与官方 `org.springframework.ai:spring-ai-session`
  同包名（`org.springframework.ai.session.*`），spring-ai 2.1.0 的
  `spring-ai-client-chat`/advisor 会把两套实现同时拉上 classpath，行为不可预测。必须切官方。淘汰。
- **本次一并改写教学课（ChatMemory → session memory）**：与升级耦合会放大回归排查面；
  废弃期到 3.0.0，时间窗充足。列入非目标。淘汰。
- **升级到 2.1.1-SNAPSHOT（本地源码）**：不可复现构建。淘汰。
