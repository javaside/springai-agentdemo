# TodoWrite「建了清单不更新」根因分析

状态：定稿 v2（2026-10-08 二次复核：将「通道错位」从根因降格为待验证假说——
tools 放置在成败两组会话中完全相同，不构成区分变量）。
关联实现：[2026-10-07-todo-stale-reminder-design.md](2026-10-07-todo-stale-reminder-design.md)（harness 兜底，已交付计数版）。

## TL;DR（已证实的结论）

**模型在严格执行 SDD skill 的流程，而那个流程的完成动作只有「往台账写一行」——不含
TodoWrite 调用（skill 全文 32922 字符，TodoWrite 字样 0 次）。** 它不是想调而忘调：
从它遵循的流程看，完成时刻该记的账已由台账行（内容即 "Task N: complete"）记完，
TodoWrite 这一步不存在。**而环境对此零反馈——没有任何机制把过期清单送回模型上下文，
后续每一轮又照抄自己第一轮的做法**，遗漏持续到会话结束。

一句话因果链：**遵循的流程里没有这一步 → 没调 → 环境零反馈 + 自我照抄 → 8 轮如一。**

## 已证实的因果链（两层）

### 层 1：模型遵循的 skill 流程里，完成动作不含 TodoWrite 调用（因）

- 事实：skill §5 的完成动作是往台账写一行（带格式模板）；台账行被逐字照抄
  （`Task 1: complete (commits e23e4fd..a3f4283, review clean)`）——模型在严格执行流程；
  流程文本全文 TodoWrite 字样 0 次。结果：8 个完成时刻、8 次台账追加、0 次 TodoWrite。
- 推断（模型内部不可观察）：skill 那半句 "mark the todo complete" 为何没产生工具调用——
  要么被台账行（内容即 "complete"）语义满足，要么被忽略。两种情况都归结为：
  **它遵循的流程不含这一步**。
- 注意：「每次只做了台账、没调 TodoWrite」这句话本身是现象的重述，不构成原因；
  本层的解释力来自「为什么没调」——因为在照一个没有这一步的流程办事。

### 层 2：零反馈 + 自我模式强化——单次遗漏永久化

- 面板是 UI 层，模型看不见；TodoWrite 返回是一次性静态文案（#126 后永不再现）；
- harness 无任何机制把过期清单重新送进模型上下文；
- 写不写 TodoWrite 对任务推进、审查结果、台账内容**没有任何可观察差异**；
- 第一轮过后，模型自己的历史示范了「审查通过 → cat >> 台账 → 派下一个」完整流程，
  LLM 对自身已建立模式的延续倾向使每一轮都在复制它。

## 待验证假说（修复方向的理论依据，非病因结论）

**「工具描述中的行为规则对非 Claude 系模型约束力弱于系统提示词，故把更新纪律写进
系统提示词可在动作竞争中胜出。」**

- 支持理由：业界双通道惯例（我们自己的系统提示词里本就有 TodoWrite 指引行）；
  Claude 系模型被训练成把工具描述当行为契约，别家无此保证。
- **不能作为病因**：见排查表 #7——`tools` 放置在成败两组间相同。
- 可证伪实验：把纪律段写进系统提示词，重跑同型 SDD 会话（同模型、同 skill），
  观察更新行为是否恢复。恢复 → 假说成立，系统提示词修法有效；不恢复 → 假说推翻，
  只能依赖运行时注入。

## 修复方案

| 修法 | 针对层 | 状态 |
|---|---|---|
| `TodoStaleReminder` 运行时注入（计数版，默认 8 次触发；事件对齐版：Task/ParallelTasks 返回即触发） | 层 2 零反馈（事件版兼补层 1：在动作选择现场递指令） | 计数版**已交付**（main）；事件版待做 |
| 系统提示词增加任务清单纪律段（含委派语义：subagent 返回过审 = 完成，先更新再继续） | 层 1 动作槽（依据上述**待验证假说**，建议先跑对照实验） | 待做 |

第三方 skill（subagent-driven-development）**一字不动**：不可控（上游重同步即覆盖）、
与工具无绑定关系、修订收益有限；曾有本地修订，2026-10-08 已恢复原样。

## 附：工具信息的放置原则（工程惯例建议）

| 信息性质 | 例子 | 放哪 |
|---|---|---|
| 接口文档：是什么、怎么调、参数/返回约束 | 入参 schema、"Pass the FULL list every call" | `tools` 字段（随 schema 走，唯一合法位置） |
| 行为纪律：什么事件必须用、用完的义务 | 「每任务完成先更新再继续」 | 系统提示词（所有模型都保证当指令读的通道） |
| 现场强制：此刻必须做 | 「subagent 刚返回、清单未动 → 现在更新」 | 运行时注入（工具结果尾部） |
