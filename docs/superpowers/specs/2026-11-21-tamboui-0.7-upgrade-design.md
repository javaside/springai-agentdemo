# Tamboui 0.4.0 → 0.7.0 升级 · 设计与执行记录

- 日期：2026-11-21
- 分支：`feature/tamboui-0.7-upgrade`
- 状态：已执行（本文件为事后补交的设计记录，评估结论先于执行经用户确认）

## 目标

`dev.tamboui` 0.4.0 → 0.7.0，拿到：安全修复 GHSA-5m5f-4gqv-8c29（0.6.0，OSC 8 超链接
控制字符注入——code-tui 渲染模型 markdown 真实命中）、CJK/i18n 加固、渲染管线 2.1×、
EventParser 输入解码修复（#611/#517/#481）、X10 鼠标与 Kitty protocol 解码。

## 非目标

- **Kitty keyboard protocol 的运行时启用**（InlineTuiRunner 层的 AUTO 探测/keyboardProtocolEnabled）：
  shadow Runner 保持 legacy 键盘路径（与 0.4 行为一致）。理由：shadow Runner 的存在意义是
  AsyncPtyWriter/防卡死定制（pty 写阻塞事故根治），0.7 的 TickTimer/Kitty 重构与该定制在同
  区域深度交织，全量 rebase 风险不成比例；EventParser 已按 0.7 rebase，Kitty 序列即使到达
  也能正确解码。后续如需 Kitty，在 0.7 shadow 基线上增量开启。
- inline-patch 之外的 Tamboui API 迁移（八课 demo 编译零错，无迁移）。

## 已核准的事实依据（评估阶段实测）

1. shadow 10 类中 7 个 0.7 字节码零变化（含 CharWidth/AsyncPtyWriter/InlineDisplay 等）；
   `InlineViewport` 源码零变（字节码差异为编译器噪声）；真变化仅 `InlineTuiRunner`/`EventParser`。
2. 编译破坏全部隔离在 patch 模块：`DiffResult` 改 run-based 协议（`add(int,int,Cell)` 移除、
   `addRun/bind` 包私有）、`TickEvent.of(long,Duration)`→`of(long)`（0.6.0 移除 elapsed）。
3. 上游 0.7 `Buffer.setString` 仍是逐 codePoint + VS16 促宽方案，**没有**本项目的
   `combiningSequenceLength`+`TerminalWidth` 组合序列方案——宽度定制必须保留。
4. 项目 EventParser 定制为成体系「粘贴快速通道」：rawBulkStream 反射穿透 + 8KB 批量读 +
   静默预算 + OVERSHOOT 溢出回灌 + BacklogBackend 装饰器（多文件拖拽事故根治）。

## Shadow rebase 策略（三档）

| Shadow 类 | 策略 | 说明 |
|---|---|---|
| `Buffer` | 0.7 底座 + 定制全保留 | 上游 diff 按 run 协议重写（shadow 在同包可调包私有 `addRun`——实际保留 0.7 上游 diff 本体）；`setString` 组合序列段与 `withLines` 的 TerminalWidth/`combiningSequenceLength` 定制原样移植 |
| `InlineTuiRunner` | **最小 rebase**（保留 0.4 shadow 主体） | 仅修 `TickEvent.of(frame)` 编译破坏；Kitty/windowTitle/TickTimer 不吸收（见非目标）；`lastTick/nextTickTime` Instant 调度与防卡死定制耦合，保持 |
| `EventParser` | 0.7 底座 + 粘贴机制块全量移植 | 0.7 的 Kitty/X10/#611 解码全量拿到；粘贴块（字段+stash+BacklogBackend+readPasteRawBulk+PasteBodyScanner+rawBulkStream）整体拼装；`readEvent` 入口回灌接缝保留 |
