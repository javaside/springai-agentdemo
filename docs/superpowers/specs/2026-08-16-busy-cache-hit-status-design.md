# 运行态缓存命中率状态栏设计

**日期**：2026-08-16
**范围**：`springai-code-tui` 状态栏展示

## 目标

在会话处于 `THINKING` 或 `RUNNING_TOOL` 时，继续显示当前会话累计缓存命中率，避免任务执行期间只能等回到 `IDLE` 才能查看。

## 设计

### 展示范围

- `THINKING`：在静态后缀中追加 ` · 缓存命中 N%`。
- `RUNNING_TOOL`：在静态后缀中追加 ` · 缓存命中 N%`。
- `IDLE`：保持现有完整后缀 ` · 上下文 N% · 缓存命中 N%`。
- 会话压缩、技能选择、斜杠菜单和等待子任务收尾等专用状态行保持现状。

忙时不显示上下文占比，只显示缓存命中率。这样可以控制状态行长度，并优先保留当前运行反馈、取消操作和动态缓存指标。

### 数据来源与时序

`ContextUsage` 增加一个只返回缓存命中段的查询方法，读取与 `suffix()` 相同的节流缓存快照。无计费输入或尚无缓存命中率时返回空串，不产生悬空分隔符。

显示值是截至最近一次已收到 usage 的当前会话累计值。正在执行且尚未返回 usage 的请求不会提前计入；现有约 1 秒的状态栏快照刷新节流保持不变。

### 状态栏拼接与宽度

缓存命中段加入 `THINKING` 和 `RUNNING_TOOL` 的静态后缀：

- 思考态：运行指示 + 队列/插话/通知 + 缓存命中率 + 取消/退出提示。
- 工具态：工具名与摘要 + 队列/插话/通知 + 缓存命中率 + 取消提示。

工具态继续复用 `fitToolSummary(...)`。缓存命中段作为 `suffix` 的一部分参与宽度预算，长工具摘要会先收缩，为缓存命中率和 `Esc 取消` 让出空间。

## 测试

新增或扩展状态栏离屏渲染测试，覆盖：

1. `THINKING` 且已有缓存统计时显示 `缓存命中 N%`。
2. `RUNNING_TOOL` 且已有缓存统计时显示 `缓存命中 N%`。
3. 无计费输入时，两种忙碌状态均不显示缓存命中段，也不产生重复分隔符。
4. 80 列终端和长工具摘要下，缓存命中率与 `Esc 取消` 仍完整可见，摘要按现有规则收缩。

## 非目标

- 不改变缓存命中率计算公式、usage 采集链路或刷新频率。
- 不把当前未完成请求的 token 预测计入命中率。
- 不改会话压缩及其他专用状态行。
- 不在忙时重复显示上下文占比。
