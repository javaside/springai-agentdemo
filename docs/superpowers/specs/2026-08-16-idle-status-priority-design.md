# 空闲状态栏信息优先级设计

**日期**：2026-08-16
**范围**：`springai-code-tui` 空闲状态栏宽度适配

## 目标

终端窗口变窄时，空闲状态栏优先保留当前模型和动态上下文信息，不再让低优先级快捷键提示把行尾的上下文、缓存命中率或后台任务状态挤出屏幕。

## 现状与问题

空闲状态栏当前按终端宽度逐段丢弃静态提示，模型名与动态后缀已经具有更高优先级。但现有实现仍有两处问题：

1. 快捷键按单段依次消失，顺序为 `Esc 取消`、`/model 切换模型`、`Ctrl+C 退出`、`Enter 发送`，窗口缩放时文案频繁变化，且不符合“次要帮助整体让位”的语义。
2. 非默认权限模式会在状态行行首追加常驻标签，但 `idleHint(...)` 的宽度预算没有扣除该标签。即使静态提示已经让位，尾部动态信息仍可能被权限标签挤出屏幕。

## 信息优先级

空闲状态栏分为三组，按以下优先级从高到低保留：

1. **核心状态**：当前模型 + 动态后缀。动态后缀包括上下文占比、缓存命中率和后台任务状态；这些信息随会话变化，必须优先完整显示。
2. **主操作**：`Enter 发送`。这是空闲态最常用操作，空间允许时保留。
3. **次要帮助组**：`/model 切换模型 · Esc 取消 · Ctrl+C 退出`。这些操作可通过 `/help` 或既有使用经验获知，空间不足时整组隐藏。

非默认权限模式标签位于核心状态之前，继续常驻显示。它决定工具调用是否会询问用户，不能作为普通快捷键提示隐藏。

## 响应式装填

完整状态行保持现有顺序：

```text
[权限模式] Enter 发送 · /model 切换模型 · Esc 取消 · Ctrl+C 退出 · <模型><动态后缀>
```

装填算法按可用宽度选择第一个能完整容纳的候选：

1. 宽窗口：显示主操作、次要帮助组和核心状态。
2. 窄窗口：整组隐藏次要帮助，显示 `Enter 发送 · <模型><动态后缀>`。
3. 更窄窗口：再隐藏 `Enter 发送`，只显示 `<模型><动态后缀>`。

计算候选宽度时，必须把非默认权限模式标签的显示宽度从终端宽度中扣除。默认权限模式没有标签，不占预算。

如果“权限模式标签 + 模型 + 动态后缀”本身已超过终端宽度，则不主动裁剪模型或动态字段。此时已经没有更低优先级信息可隐藏，由终端执行最终裁切；实现不制造半个字段、省略动态数值或悬空分隔符。

## 实现边界

保留 `statusLine()` 作为状态分发和组装入口。仅调整空闲分支调用的宽度装填逻辑：

- 让装填方法接收权限模式标签占用的显示宽度，或等价的可用宽度；
- 将静态提示从四个独立元素改为“主操作 + 次要帮助组”两个语义候选；
- 继续使用现有 Unicode 显示宽度计算，不能用 Java 字符串长度代替终端列宽。

不引入新的布局组件，不改变状态栏样式、颜色、顺序或动态数据来源。

## 测试

使用离屏渲染测试覆盖真实状态行文本，而非只测内部字符串帮助方法：

1. **宽窗口**：完整显示 `Enter 发送`、`/model 切换模型`、`Esc 取消`、`Ctrl+C 退出`、模型和动态后缀。
2. **窄窗口**：次要帮助组三段全部消失，`Enter 发送`、模型和动态后缀完整保留；不得只隐藏组内部分文案。
3. **更窄窗口**：`Enter 发送` 也消失，模型和动态后缀仍完整保留。
4. **非默认权限模式**：权限标签存在时参与宽度预算；窄窗口下标签与模型、上下文和缓存命中率完整可见，次要帮助组按规则让位。
5. **边界完整性**：候选恰好等于可用宽度时应显示，不因 `<=` / `<` 边界错误提前降级。

测试应先证明当前实现会因“整组隐藏”要求或权限标签预算缺失而失败，再修改生产代码。

## 非目标

- 不修改 `THINKING`、`RUNNING_TOOL`、压缩、选择器、审批等专用状态行。
- 不改变上下文占比、缓存命中率或后台任务状态的计算与刷新频率。
- 不截短模型名，不缩写动态字段，不新增省略号策略。
- 不改变权限模式标签的文字、样式或显示条件。
